# I2: Patrol E2E staging(http) 모드 Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** 지금 fake 모드로만 도는 Patrol E2E를 같은 테스트 그대로 staging server에 붙여(http 모드) 로컬 에뮬레이터에서 끝까지 돌리고, 결과를 #781에 보고합니다.

**Architecture:** 테스트 모드는 dart-define `E2E_MODE`(`fake` 기본, `staging`)로 고릅니다. staging 모드의 로그인과 데이터 준비는 Mac에서 도는 작은 relay(`tool/e2e_staging/relay.dart`)가 맡습니다. relay만 `TEST_LOGIN_SECRET`을 메모리에 들고 server 테스트 경로(S24 로그인, S125 광고 제거 기간)를 부르고, 앱은 `adb reverse`로 relay에 닿습니다. 비밀은 빌드 산출물(dart-define)에도 기기에도 들어가지 않습니다(D98). 앱 쪽은 테스트 코드가 실제 로그인 SDK, 결제, 푸시를 대역으로 바꾸고, 로그인 요청(`/v1/auth/<제공자>`)을 relay로 돌리는 Dio interceptor를 끼웁니다.

**Tech Stack:** Flutter, Patrol 4.10 / patrol_cli 4.8.0, Riverpod 3.4.3, Dio, `dart:io` HttpServer(relay), gcloud CLI, adb.

**Spec:** Issue #781(로드맵 I2) 본문. server 쪽 근거는 `server/docs/specs/2026-10-11-server-mvp-design.md` §13.2(S24, S125)와 `server/internal/httpapi/testlogin_staging.go`, 보상 경로 S131, staging 광고 D101/A106.

## Global Constraints

* fake 모드 PR CI(`e2e-android`)와 `tool/patrol_local.sh`의 기본 동작은 바꾸지 않습니다. `E2E_MODE` 기본값은 `fake`입니다.
* `TEST_LOGIN_SECRET`은 relay 프로세스의 메모리에만 있습니다. 출력, 파일, dart-define, 명령줄 인자, 환경 변수 어디에도 남기지 않습니다(gcloud 출력을 relay의 stdin으로 바로 넘김).
* relay는 `127.0.0.1`에만 bind하고 포트는 47283입니다(47281/47282는 Patrol, 8081 회피).
* label 형식은 `e2e` + 밀리초 시각 + 영숫자 4자, 32자 이하입니다(`^[A-Za-z0-9]{1,32}$`).
* 실행이 끝나면(성공, 실패, 중단 모두) 그 실행이 만든 모든 label의 계정을 지웁니다.
* app 코드(`lib/`) 변경은 `bootstrap`의 실제 플랫폼 override 건너뛰기 하나뿐입니다. 테스트 전용 코드는 `patrol_test/`와 `tool/`에 둡니다.
* 문의 흐름의 내용 첫머리는 `[E2E]`입니다(staging 메일함에서 가려 볼 수 있게).
* 사용자에게 보이는 글은 만들지 않습니다(D93 해당 없음). 결정 번호는 A108입니다.

## Review Focus

1. 테스트가 중간에 죽거나 Ctrl-C로 끊겨도 staging에 테스트 계정이 남지 않아야 합니다(relay가 label을 기억하고 wrapper `trap`이 정리).
2. relay가 뜨지 않았거나 비밀을 못 읽었을 때 테스트가 모호한 시간 초과가 아니라 "relay 준비 안 됨"으로 바로 끝나야 합니다.
3. staging의 실제 오늘 날짜가 달 말일, 1일이어도 달력과 일기 흐름의 날짜 계산이 맞아야 합니다(다음 달, 3일 전).
4. relay 응답의 server 오류(4xx, 5xx)가 그대로 앱에 가서 화면 오류로 보이고, relay 로그에는 경로와 상태만 남아야 합니다(본문, 토큰, 비밀 없음).
5. fake 모드에서 새 문의, 계정 삭제 흐름과 날짜 계산 리팩터가 기존 흐름 결과를 바꾸지 않아야 합니다.
