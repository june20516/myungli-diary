# app IA v3 Implementation Plan (출생지 표준 소개·계산 기준)

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** IA v3(D71)를 반영합니다. `birthplace`에 한국 표준 소개와 계산 기준 링크(`depth-link` `navigate`)를 두고, `calc-basis` 화면을 만들어 로그인 전(온보딩 출생지)에도 엽니다. 경도 안내는 출생 시간대·출생 시각에 맞는 키(#184)로 값을 넣어 보입니다.

**Architecture:** 새 feature `lib/features/calc_basis/`에 경도 보정 계산(`model/`), 음력→양력 변환 저장소(`data/`), 화면이 쓸 provider(`application/`), 화면(`presentation/`)을 둡니다. 보정 값은 엔진(`core/src/myungli_engine/calendar_core/birth.py` `resolve_birth_moment`, `constants/longitudes.py`)과 같은 규칙으로 app이 계산합니다. 입력은 로그인 전이면 온보딩 입력(`onboardingDraftProvider`), 로그인 뒤 프로필 사본이 있으면 그 사본의 `birth`입니다. 라우터는 `calc-basis`(`auth: any`)를 온보딩 갈래에서도 허용합니다.

**Tech Stack:** 계획 3과 같음(Flutter stable, Riverpod 3.x, go_router, Dio 생성 클라이언트, `timezone`). 새 패키지 없음.

**Spec:** 별도 spec 없이 다음이 기준입니다. IA `docs/ia/screens.json` v3의 `birthplace`·`calc-basis`, 결정 D28·D42·D71(`docs/decisions.md`), design V32와 `docs/identity/design/specs/2026-10-15-spec-followups-design.md` §4·`components/sentence.md` `navigate`, writing 요청 #184, 지휘 요청 #160·drift #173, app 구조 spec `app/docs/specs/2026-10-13-app-architecture-design.md`.

## 이 계획이 정하는 것 (계약 사이 빈칸)

| 빈칸 | 정한 것 |
| --- | --- |
| 경도 안내의 기준 경도·보정 분을 app이 어디서 얻는가 | **A28:** 엔진 규칙을 그대로 app에서 계산합니다. 기준 경도 = 도시 경도, 없으면 대표 경도(`Asia/Seoul`은 127.5, 그 밖은 표준 오프셋 × 15). 표준 오프셋은 **출생 시각**(양력 날짜 + 시각, 시각 모름은 12:00)에 출생 시간대의 서머타임을 뺀 오프셋입니다. 그래서 1954-03-21~1961-08-09 서울 출생은 표준 자오선이 127.5°라 보정이 없습니다. 보정 분 = (기준 경도 − 표준 오프셋 × 15) × 4를 반올림한 값이고, 양수면 `Add`, 음수면 `Subtract`(절댓값), 0이면 `None` 키입니다. 경도 표기는 소수 둘째 자리까지, 뒤의 0을 지운 문자열이고 0 이상이면 `East`, 음수면 `West`(절댓값)입니다. 음력 생일은 `convertLunarDate`로 양력 날짜를 얻습니다 |
| 도시를 고른 출생(`BirthPlace.status == city`)의 경도가 REST 계약에 없음(server는 저장하지만 응답에 넣지 않음) | **A29:** 도시 경도를 모르면 경도 문단(`calc-basis.longitude.body`)을 그리지 않고 자리도 남기지 않습니다(A22와 같은 방식). 음력 변환이 실패해도 같습니다. server에 `City.longitude`와 프로필에서 출생 도시 경도를 얻는 방법을 요청합니다(Task 1). 계약에 들어오면 입력 연결만 더합니다 |
| `calc-basis`에 제목 슬롯이 없음 | **A30:** app 임시 ARB `calcBasisTitle`("계산 기준", IA `title`)을 app-bar `inner` 제목으로 둡니다(A27과 같은 방식). 지휘에 IA 슬롯 추가를 요청합니다(Task 1) |
| `birthplace`의 소개·링크 자리 | design spec §4대로 질문 아래, 검색칸 위에 `birthplace.standard.note`(`input-step` 도움말과 같은 글자 스타일)와 그 바로 아래 `depth-link` `navigate`(`marginTop` `space.12`)를 둡니다. `InputStep`에 입력 위 자리(`preface`)를 더해 다른 단계도 쓸 수 있게 합니다. 수정 모드(`?mode=edit`)에도 보입니다 |
| `calc-basis`를 여는 갈래 | 로그아웃(`signedOut`)은 `auth: any`라 이미 열립니다. 온보딩 갈래(`profileRequired`)의 허용 목록에 더하고, `ready`에서는 그대로 열립니다. `settings` → `calc-basis` 출구는 설정 화면을 만드는 계획(계획 6)에서 잇습니다 |

## Global Constraints

* 기반·계획 2·3 plan의 Global Constraints를 모두 따릅니다(`app/docs/plans/2026-10-13-foundation.md`, `2026-10-14-onboarding-login.md`, `2026-10-15-today-depth.md`). 경고 0, 생성 코드 손대지 않음, 토큰 의미 역할만, Material 효과 끔·스피너 금지, ARB 경유, IA id를 Key와 Semantics `identifier`로, 한국어 주석과 `feat(app):` 형식 commit, TDD, D64.
* 의존 방향은 presentation → application → data → core이고, feature끼리는 application provider로만 참조합니다(`feature_layering_test` 허용 목록은 빈 채로).
* **재사용·확장·사용감(사용자 지시):** 경도 계산은 화면과 떨어진 순수 함수로, 다른 화면(`saju-chart` 등)이 다시 쓸 수 있게 합니다. `InputStep`의 새 자리는 일반 이름으로 둡니다. 링크는 `press.ink`, 페이지 이동은 플랫폼 기본 전환, 스크린리더 role은 `link`입니다.
* 공개 저장소(D74): 가격·수익 수치, 비공개 경로 링크를 적지 않습니다.

## Review Focus

* 1955년 6월(서머타임 기간) 서울 출생: 표준 오프셋 8.5 → 보정 없음(`None`, 동경 127.5°). 서머타임 1시간을 표준 오프셋에 넣으면 틀립니다.
* 1987년 7월(서머타임 기간) 서울 출생: 표준 오프셋 9 → 30분 빼기.
* 음력 생일이 1961년 경계 근처(음력 1961-07-01 → 양력 8월 중순): 변환한 양력 날짜로 오프셋을 봅니다. 변환 실패(오프라인)면 경도 문단만 빠지고 나머지 세 문단은 보입니다.
* 시각 모름: 12:00으로 계산합니다(엔진 `UNKNOWN_TIME_FALLBACK`).
* `birthplace`에서 검색어를 입력하고 결과가 나온 뒤 계산 기준에 갔다 돌아오면 검색어와 결과가 그대로입니다.
* 글자 크기 최대(textScaler 2.0)에서 `calc-basis` 본문이 스크롤되고 넘치지 않습니다.
