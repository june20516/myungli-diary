# app 일기 Implementation Plan (계획 5)

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** fake 모드에서 회원이 `diary` 탭(`diary-list`)에서 쓴 일기를 날짜 내림차순으로 넘겨 보고, 날짜를 골라(미래 제외) 쓰거나 보고, `diary-edit`에서 그날 가이드 질문을 보며 쓰고 고치고(기기 초안 자동 저장, 오프라인이면 초안만), 저장하면 도장이 찍히고 태그가 붙습니다. `diary-view`에서 본문·그날 성격·태그를 보고 고치기·지우기를 하고, 태그 칩을 누르면 `tag-diary`에서 같은 태그 일기와 태그 뜻을 봅니다.

**Architecture:** `lib/features/diary/`에 data(일기 저장소 확장·초안 저장소)·application(목록 쪽 넘김·그날 일기·초안·저장 상태)·presentation(화면 4개)을 둡니다. 일기 목록은 메모리에만 들고(쪽 단위), 초안은 drift `DiaryDrafts`(계정·날짜)에 둡니다. 새 컴포넌트 `tag-chip`·`diary-row`·`diary-editor`·`draft-indicator`와 `date-picker` `calendar` 변형은 `lib/design/components/diary/`·`input/`에 둡니다. 날의 성격은 계획 4의 달 길흉 영구 캐시(`calendarDayProvider`)를 다시 씁니다.

**Tech Stack:** 계획 4와 같음(Flutter, Riverpod 3.x 코드 생성 없음, go_router, Dio 생성 클라이언트, drift, `intl`). 새 패키지 없음.

**Spec:** `app/docs/specs/2026-10-13-app-architecture-design.md`(§4.4 캐시, §10 계획 5). 화면은 IA `docs/ia/screens.json` v3(`diary-list`·`diary-edit`·`diary-view`·`tag-diary`), 컴포넌트는 `docs/identity/design/components/diary.json`·`.md`(2.6.0, V16·V20), `input.md`(`date-picker` `calendar`), `feedback.md`(`dialog` `destructive`·`toast`·`notice-banner`). REST는 `server/api/openapi.yaml` 1.0.0-draft.7(`listDiaries`·`getDiary`·`putDiary`·`deleteDiary`, `getDaily` `guide`, `getGlossary` `meanings`). 제품 결정 D22·D47①②·D49·D64·D75.

## Global Constraints

* 기반·계획 2·3·4 plan의 Global Constraints를 모두 따릅니다(경고 0, 생성 코드 손대지 않음, 토큰 의미 역할만, Material 효과 끔·스피너 금지, ARB 경유, IA id를 Key와 Semantics `identifier`로, 한국어 주석과 `feat(app):` commit, TDD, D64: 일기 본문·태그를 crash 기록에 싣지 않음).
* 의존 방향 presentation → application → data → core, feature끼리는 application provider와 `model/`만(`feature_layering_test` 허용 목록 빈 채로).
* 컴포넌트 변형·상태 id는 명세 그대로 enum이고 `ComponentSpec`으로 `component_contract_test`가 대조합니다. 새 컴포넌트는 golden과 Widgetbook use case를 둡니다.
* 값은 `diary.json` 그대로: `diary-row` 날짜 열 44·숫자 18 600·도장 soft 34·`rail.timeline` 1.5, 카드 `bg.sheet` `radius.lg`, 미리보기 `sentence-block` `preview`; `diary-editor` `surface.paper`, 아래 도장 자리 64(쓰는 중에도 비워 둠), 도장 안 날짜 `M.D` `seal.knock`; `tag-chip` 높이 26 `type.label.md` 12 `radius.full`, 변형 `good`·`bad`·`neutral`; `draft-indicator` 상태 `local`·`saving`·`saved`, 아이콘 16 Light.
* 하루 1편, 미래 날짜는 쓸 수 없음(D49). 해시태그 입력 없음(D13). 일기는 공유하지 않음(D47④).
* **재사용·확장·사용감(사용자 지시):** `tag-chip`은 목록·보기·저장 순간에 한 컴포넌트, 쪽 넘김 목록은 `diary-list`·`tag-diary`가 같은 provider 틀을 씁니다. `date-picker` `calendar`는 계획 4의 `CalendarMonthView`·달 계산을 다시 씁니다. 저장 순간 동작은 reduce motion이면 opacity만입니다.
* 공개 저장소(D74): 가격·수익 수치, 비공개 경로 링크를 적지 않습니다.

## Review Focus

1. 오프라인에서 쓰기 화면을 열고 글을 쓴 뒤 앱을 다시 열면 초안이 남아 있고(`draft`), 저장이 연결 오류로 실패하면 배너가 보이고 초안은 그대로입니다.
2. 저장 버튼을 빠르게 두 번 눌러도 `putDiary`는 한 번이고, 저장 실패 뒤에도 초안이 그대로입니다.
3. 오늘 자정을 넘긴 채 날짜 시트를 열면 새 오늘까지 고를 수 있고 그 뒤는 막힙니다. 서버가 422 `diary.future_date`를 주면 문구 toast이고 초안은 남습니다.
4. 목록 끝까지 빠르게 밀어도 같은 `cursor` 요청은 한 번만 나가고, 마지막 쪽(`nextCursor` 없음) 뒤에는 더 묻지 않습니다.
5. 저장·삭제 뒤 돌아온 목록·달력 도장·오늘 가이드 카드(쓴 뒤)·그날 시트 입구가 모두 새 상태입니다.
