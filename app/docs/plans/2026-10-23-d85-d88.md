# 계정 삭제·구매 내역 따라잡기 (D85·D88) Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** drift #504와 REST draft.15(#518)를 맞추고, 계정 삭제를 D85 ⑤(즉시 삭제)로 바꾸고, 광고 제거·구매 내역 화면(#493)을 만들고, 계획 7 문서를 D85에 맞게 고칩니다(#484).

**Architecture:** 생성물과 문구를 먼저 반영해 컴파일을 되살리고, 계정 삭제·진입 계산에서 삭제 대기 갈래를 지웁니다. 구매는 플랫폼 인터페이스 `Purchases`(sync·상품 이름) → `PurchaseRepository`(listPurchases·restorePurchases) → 구매 내역 controller(숨은 다시 맞추기) → 두 화면 순으로 쌓습니다. 새 컴포넌트 `offer-card`·`purchase-row`는 design 3.0.0 명세 값 그대로 만들고 contract·golden·widgetbook으로 고정합니다.

**Tech Stack:** Flutter 3.47.7, Riverpod 3.x(코드 생성 없음), go_router, Dio 생성 클라이언트(openapi-generator), drift, `intl` `DateFormat`, 생성자 문법 `const new(...)`.

**Spec:** `app/docs/specs/2026-10-23-d85-d88-design.md`

## Global Constraints

* 문구 키는 writing ARB의 것만 씁니다. 예외는 구매 버튼 임시 키 `adFreeBuyCta`("구매하기", en "Buy", ja "購入する") 하나입니다(spec §6, A7).
* 광고 제거권 상품 id는 저장소 코드에 넣지 않습니다(S89, D74). 빌드 설정 `--dart-define=AD_FREE_PRODUCT_IDS`(쉼표 목록)로 받고, fake 모드에서 비어 있으면 fake 카탈로그 id `ad_free_1month`입니다. fixture·fake의 이 id는 기존 값 그대로입니다.
* 가격·수익 수치를 코드·fixture·문서에 적지 않습니다(D74). fake 가격은 지금처럼 `'—'`입니다.
* 오류 보고는 `CrashSummary`(`guardUnexpected`)만 씁니다. 구매 내역·상품 정보를 로그·CrashReporter에 싣지 않습니다(D64).
* 구매 목록 순서는 server 순서 그대로입니다. app이 다시 정렬하지 않습니다.
* 날짜는 기기 시간대 기준이고, 구매일·기간은 기기 locale의 짧은 날짜(`DateFormat.yMd(locale)`)입니다. `diary-row` entry 시각은 locale과 상관없이 `HH:mm`입니다.
* 상태 낱말: `active`→`purchaseStatusActive`, `pending`→`purchaseStatusPending`, `expired`→`purchaseStatusExpired`, `refunded`→`purchaseStatusRefunded`, `owned`·모르는 값→없음(상태 자리 비움).
* 결정 번호 A73~A77(spec §9). 결정 행 근거 칸에 `사용자 영향:`을 적습니다(D87): A73 `D85`, A74 `없음`, A75·A76·A77 `D88`.
* 계획 7 문서의 결정 번호는 A78부터입니다.

## Review Focus

1. 구매 내역에 들어갔는데 `sync`나 `restorePurchases`가 실패(오프라인·503)해도 목록이 보여야 하고, 오류 toast·dialog가 뜨면 안 됩니다.
2. 계정 삭제 204 뒤 server `logout`을 부르면 안 됩니다(세션이 이미 없어 401 → refresh 시도 → 이중 로그아웃 이벤트).
3. 광고 제거 구매 성공 뒤 `restorePurchases`가 실패해도 성공으로 끝나고 `Me`는 다시 받아야 합니다(사용자는 결제했는데 화면이 실패라고 말하면 안 됨).
4. `period`가 없는 `expired` 구매와 `owned`·모르는 상태가 와도 줄이 깨지지 않고 구매일만·상태 없음으로 보여야 합니다.
5. 구매 중에 구매 버튼을 다시 누르거나 화면을 나갔다 와도 `buy`가 두 번 불리지 않아야 합니다.

각 줄의 테스트: 1은 Task 5(controller)·Task 9(화면), 2는 Task 1, 3은 Task 8, 4는 Task 4(이름·낱말 함수)·Task 7(golden 기간 없음)·Task 9, 5는 Task 8.
