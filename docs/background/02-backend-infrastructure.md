# 2. 백엔드 인프라 구조 설계서

## 2.1. 마이크로서비스(MSA) 기반 분리 구조
1. **클라이언트 (Flutter App):** 사용자의 요청(일기 저장, 스케줄 조회 등)을 API Gateway 로 전송.
2. **API Gateway / 메인 서버 (Go):** 
   * 라우팅 및 유저 인증 로직 수행.
   * 일기 작성, 데이터 동기화 등 일반적인 비즈니스 로직은 PostgreSQL에 직접 쿼리하여 처리.
   * 명리적 계산이 필요한 경우만 Python 명리 엔진 서버로 요청 전달.
3. **명리 엔진 (Python):** 
   * Go 서버로부터 사용자의 생년월일시 또는 특정 날짜를 인풋으로 받음.
   * 자체 만세력 알고리즘을 구동하여 합충변화, 용신/희신 오행을 계산.
   * 연산된 JSON 결과를 Go 서버로 반환.
4. **배치 스케줄러 (Go / Cron):** 
   * 매일 자정, 전체 유저의 내일자 데일리 추천 데이터(방위, 시간, 색상)를 미리 계산하여 Redis에 적재.

## 2.2. 데이터 동기화 및 외부 연동
* **클라우드 동기화:** 다중 기기 지원을 위해 타임스탬프(수정 시간) 기반의 Sync-token 아키텍처 적용 (오프라인 작성 후 온라인 전환 시 충돌 해결 로직 포함).
* **외부 캘린더 연동:** 내부에서 생성된 스케줄 및 캘린더 정보를 iCalendar(.ics) 포맷이나 Google/Apple Calendar API를 통해 외부로 동기화. 스케줄 목적이나 길흉 정보를 색상 태그로 맵핑.
