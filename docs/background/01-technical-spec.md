# 1. 기술 명세서 (Technical Specification)

## 1.1. 프론트엔드 (클라이언트)
* **프레임워크:** Flutter (iOS / Android 크로스 플랫폼 동시 지원)
* **상태 관리:** Provider 또는 Riverpod (점진적 정보 노출 및 캘린더 UI 상태의 효율적 전역 관리)
* **UI/UX 특징:** 
  * 점진적 정보 노출(Progressive Disclosure) 아키텍처 구현 (툴팁, 바텀시트 활용).
  * 캔버스 캡처 기능(RenderRepaintBoundary)을 활용한 SNS(인스타그램, 카카오톡) 이미지 공유 템플릿 생성.

## 1.2. 백엔드 (서버)
* **메인 API 서버:** Go (Golang)
  * 역할: 유저 인증(JWT), 일기 데이터 CRUD, 클라우드 동기화, 커뮤니티 데이터 서빙.
  * 장점: 높은 동시성 처리 성능으로 대규모 일기 저장 및 기기 간 동기화 I/O에 최적화.
* **명리 엔진 서버:** Python (FastAPI 또는 Django)
  * 역할: 천문/역법 계산을 통한 만세력 사주 추출(60갑자, 대운, 세운) 및 명리 연산 전담.
  * 통신: 메인 API 서버(Go)와 내부망에서 gRPC 또는 REST API를 통해 결과 송수신.

## 1.3. 데이터베이스 및 인프라
* **메인 DB:** PostgreSQL (RDBMS)
  * 용도: 유저 계정 정보, 일기 텍스트, 명리 데이터 태깅(해시태그) 저장 및 향후 커뮤니티 관계형 데이터 처리.
* **캐시 DB:** Redis (NoSQL)
  * 용도: 매일 갱신되는 데일리 맞춤 운세(옷 색깔, 방위, 시간 등) 및 캘린더 길흉일 데이터 캐싱.

## 1.4. 데이터 통신 구조
* 클라이언트가 화면을 렌더링할 때, 직관적인 결과 텍스트(Easy 텍스트)와 그 근거가 되는 원시 명리학 데이터(Pro 파라미터)를 하나의 JSON 객체로 묶어서 반환받아, 네트워크 지연 없이 상세 뷰를 펼칠 수 있도록 설계.
