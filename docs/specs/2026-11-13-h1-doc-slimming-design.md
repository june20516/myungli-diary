* 상태: 사용자 설계 승인(대화, 2026-11-13). 이 spec 검토 뒤 계획을 씁니다

## 1. 목적

세션이 일을 시작할 때 읽는 문서에 이미 끝난 일의 경과가 쌓였습니다. 그래서 두 가지 문제가 생겼습니다.

* 읽어야 할 규칙과 사실이 많아져 세션이 규칙을 놓칩니다. 2026-11-13 지휘가 결정과 Issue 번호에 요약을 붙이지 않은 일이 그 예입니다(사용자 지적).
* 옛 문장을 지금 사실로 잘못 읽을 위험이 커집니다.

H1은 처음 읽는 문서에 **지금 맞는 사실과 규칙만** 남기고, 경과는 별도 파일로 옮기거나 지웁니다. 크기 상한 검사로 다시 불어나지 않게 막습니다.

**성공 기준:** 세션 시작 때 읽는 양이 크게 줄었다는 재측정(§7), 크기 상한 검사가 `ci-gate`에서 돌고 면제 목록이 비어 있음.

## 3. 기계 검사로 옮기는 기준

규칙을 hook이나 CI 검사로 옮기는 것은 아래 세 조건을 **모두** 만족할 때뿐입니다(사용자 승인 2026-11-13). 나머지 규칙은 문서에 남깁니다.

1. 글자만 보고 위반을 확실히 가를 수 있습니다(맥락 판단 없음).
2. 문서에 적었는데도 다시 어긴 기록이 있습니다(지휘 메모리의 재발 기록).
3. 잘못 걸렸을 때 비용이 작습니다. 막는 것은 확실한 경우만, 애매하면 경고만 합니다.

저장소에 남는 산출물(원고, PR 본문, 문서)은 CI 검사(`tools/docs-check`, `ci-gate`)를 먼저 씁니다. 대화 출력처럼 CI가 볼 수 없는 것만 세션 hook으로 둡니다.

2026-11-13 적용 결과: 재발 기록이 있는 규칙은 한국어 진행 설명(이미 hook)과 번호 요약(판단형, 조건 1 불충족)뿐이라 **새 hook은 없습니다.** 새 검사는 §5의 크기 상한 하나입니다.

**원칙**

* 내용은 바꾸지 않고 옮기거나 지우기만 합니다. 옮기다 모순을 찾으면 그 자리에서 고치지 않고 Issue로 올립니다.
* D, C, S, A, W, V, E, K 번호와 Issue 링크는 그대로 둡니다. 옮긴 문서를 가리키던 링크는 `docs-check` 링크 검사로 확인합니다.
* 일부만 대체된 결정(①은 대체, ②는 유효)은 행을 남기고 대체된 항목만 "→ <새 번호>"로 줄입니다. 원문 행은 history에 그대로 옮깁니다.
* `CLAUDE.md` "현재 상태"는 앞으로 진행 중인 일만 적고, 병합하면 지웁니다. 이 규칙을 `docs/workflow.md` §3 마무리 단계에 넣습니다.

## 5. 크기 상한과 검사

| 문서 | 상한(바이트) |
| --- | --- |
| 루트 `CLAUDE.md` | 10,240 |
| 단위 `CLAUDE.md` 5개 | 각 16,384 |
| `docs/workflow.md` | 28,672 (처음 22,528에서 실행 중 올림: 경과를 옮긴 뒤 남은 약 26.7KB가 모두 지금 규칙이고 여유 2KB를 둠, 2026-11-14) |
| `docs/roadmap.md` | 10,240 |
| `docs/contracts/README.md` | 12,288 |

* 결정 로그와 history 파일에는 상한을 두지 않습니다. 결정이 늘면 같이 커지는 참고 문서이고, 번호로 찾아 읽습니다.
* `tools/docs-check/docs_check.py`에 크기 검사를 더합니다. 상한을 넘으면 오류이고, 오류 글에 "경과를 경과 파일로 옮기거나 병합된 현재 상태를 지우세요"를 적습니다. `ci-gate`의 docs 검사로 모든 PR에 걸립니다.
* **면제 목록:** 아직 정리하지 않은 파일은 면제 목록에 둡니다. 면제 중인 파일이 상한 아래로 내려오면 검사가 "면제를 지우세요" 오류를 냅니다. 면제는 지휘가 root PR로 지웁니다.

## 6. 진행 순서

1. **지휘 root PR:**
   * 결정 D131로 규칙을 기록합니다(§3 기준, §4 모양, §5 상한, 현재 상태 규칙).
   * `docs/workflow.md` §3 마무리에 현재 상태 규칙을 넣습니다.
   * 루트 문서를 정리합니다(`docs/workflow.md`, `docs/roadmap.md`, `docs/contracts/README.md`, `docs/decisions.md`, 루트 `CLAUDE.md`).
   * `CHANGELOG.md`, `workflow-history.md`, `roadmap-history.md`, 루트 `decisions-history.md`를 만듭니다.
   * 크기 검사를 넣습니다. 단위 `CLAUDE.md` 5개는 면제 목록에 둡니다.
2. **단위 요청 5개(core, server, app, writing, design)를 동시에:** 각 단위가 자기 `CLAUDE.md`(§4)와 자기 결정 로그의 대체된 원문을 정리합니다. 소유 경로 규칙(`docs/workflow.md` §2)대로 자기 파일만 고칩니다. 진행 중인 기능 작업이 있으면 다음 PR에 묶어도 됩니다(D100 ①).
3. **면제 지우기:** 단위 PR이 병합될 때마다 지휘가 그 파일의 면제를 지웁니다.
4. **마무리:** 면제가 모두 지워지면 §2와 같은 방식으로 다시 재서 §7에 남기고, 로드맵 H1을 끝냅니다.
