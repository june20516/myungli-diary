# 명리 엔진 설계 (Myungri Engine Design)

* 작성일: 2026-10-10
* 대상: 명리일기 서브 프로젝트 1 — Python 명리 엔진 (MVP 범위)
* 상위 문서: `docs/background/` (특히 07 엔진 위키 v1.4), 결정 로그 `docs/decisions.md` (D1~D32)
* 근거 자료: `docs/references/`

---

## 1. 목적과 성공 기준

### 1.1. 목적
생년월일시(와 출생 시간대)로 원국을 세우고, **일진 × 원국**(D13)으로 사람마다 다른 하루의 판정을 계산합니다. 화면 렌더링과 문장 생성은 하지 않습니다(D27). Go 메인 서버가 gRPC로 호출합니다(D26).

### 1.2. 성공 기준
1. **천문 정확성:** 절기 입절 시각과 양력↔음력 변환이 KASI 데이터와 일치합니다(§13.2).
2. **관례 정합성:** 경계 사례 묶음에서 사주팔자와 대운 시작 나이가 기준 앱(포스텔러 만세력·사공만세력)의 기본 설정 결과와 일치합니다. 다르면 차이와 채택 근거를 기록합니다(§13.3, D10).
3. **설명 가능성:** 모든 판정에 근거(`rule_id`, `source_ref`)가 붙고, 모든 `source_ref`가 실제 근거 데이터를 가리킵니다(§13.5).
4. **결정성:** 같은 입력과 같은 `ruleset_version`이면 항상 같은 출력이 나옵니다.

### 1.3. 범위
| 포함 (MVP) | 제외 |
| --- | --- |
| 원국: 사주팔자, 십성, 지장간, 12운성, 주요 신살, 공망 (D18-⑥) | 궁합, 여러 사람 비교 (Phase 2) |
| 대운·세운 표 (D18-⑦) | 대운 흐름 시각화용 가공 데이터 (Phase 2) |
| 용신·희신·기신 판정과 근거 (D7) | 통관·병약·격국 용신 (Phase 2 이후) |
| 데일리: 날의 성격, 행운 컬러·방향·숫자, 집중 시간, 해시태그, 총운·가이드 질문 메시지 코드 | 목적별 택일 (Phase 2) |
| 월간 캘린더: 날짜별 길흉 수준, 음력 날짜, 절기 (D18-⑧) | 문장 생성, 다국어 (Go 콘텐츠 모듈, D27) |
| 시간 모름(3주), 음력·윤달 입력, 출생 시간대 일반화 (D18·D29) | 캐시·배치·알림 발송 (Go 서버, D31) |

## 2. 아키텍처

### 2.1. 실행 형태
* Python 3.13, 상태 없는 gRPC 서버(`grpcio`). DB를 쓰지 않습니다.
* 외부 계산 의존성은 `lunar-python`(MIT) 하나이며, `calendar_core` 안에서만 import합니다(D9).
* 표준 라이브러리 `zoneinfo`로 시간대 이력과 서머타임을 처리합니다(D5).

### 2.2. 모듈 구조
위층은 아래층에만 의존합니다.

```
myungri_engine/
  grpc_api/        gRPC 서비스. proto 메시지 ↔ 도메인 객체 변환만 담당
  composers/       화면 단위 조립: chart / daily / month
                   Judgment(메시지 코드·매개변수·근거) + Pro 원본 데이터 + notices
  rules/           판정 규칙. 파일 하나에 규칙 하나, 순수 함수
    strength.py        신강·신약 점수와 등급 (§6.1)
    yongsin.py         용신·희신·기신 (§6.2)
    day_kind.py        날의 성격 4단계 (§7.1)
    color.py · direction.py · number.py · focus_time.py   데일리 카드 (§7.2~7.5)
    relations.py       합·충·형, 탐합망충 (§7.6)
    shinsal.py         신살 (§5.4)
    tags.py            해시태그 (§7.7)
    messages.py        총운·가이드 질문 메시지 코드 선택 (§7.8)
    calendar_luck.py   월간 길흉 수준 (§8)
  chart/           원국·대운·세운 계산 (§5)
  calendar_core/   시각 변환: 현지 시각 → 절대 시각 → 절기 비교용 / 시주용 보정 시각 (§4)
                   lunar-python 어댑터
  domain/          enum과 값 객체: Stem, Branch, Element, TenGod, Pillar 등
  constants/       조후표, 천을귀인표, 합화표, 신살표, 하도수, 팔괘 방위, 대표 경도
  references/      docs/references 근거 데이터 로더 (패키지에 함께 배포)
```

### 2.3. 설계 규칙
* `rules/`는 문장을 만들지 않고 판정값과 근거만 반환합니다. 근거는 판정과 같은 객체로 함께 다닙니다.
* 천간·지지·오행·십성은 문자열이 아니라 enum입니다. 표기(甲 / 갑 / Kō)는 콘텐츠 계층이 정합니다.
* 상수표는 `constants/`에만 둡니다. 근거 자료와의 정합성은 테스트로 지킵니다(§13.5).

## 3. 입력 모델

```
BirthInfo
  calendar:        SOLAR | LUNAR
  is_leap_month:   bool                   (LUNAR일 때만 의미)
  date:            연·월·일 (현지 달력 기준)
  time:            시·분 | 없음            (없음 = 시간 모름)
  gender:          MALE | FEMALE          (대운 방향 계산용, D18-③)
  timezone:        IANA 문자열, 예 "Asia/Seoul"
  longitude:       실수 | 없음            (동경 +, 서경 -)
```

* 앱 1차 구현은 `timezone = "Asia/Seoul"`, `longitude = 없음`으로 호출합니다(D29).
* 음력 입력은 `calendar_core`가 먼저 양력으로 바꿉니다. 그해에 없는 윤달이면 `INVALID_ARGUMENT`입니다.
* 지원 범위: 양력 **1900-01-31 ~ 2099-12-31** 출생. lunar-python으로 음력 변환이 확인된 범위입니다(2026-10-10 실행). 범위 밖이면 `OUT_OF_RANGE`입니다.

## 4. 시각 처리 (`calendar_core`)

### 4.1. 처리 단계
1. **현지 시각 → 절대 시각(UTC):** `zoneinfo`로 출생 당시의 오프셋과 서머타임을 반영합니다.
   * 중복 시각(서머타임 종료 직전): 앞의 시각(서머타임 적용, `fold=0`)으로 해석하고 `notice: AMBIGUOUS_LOCAL_TIME`을 붙입니다.
   * 공백 시각(서머타임 시작으로 건너뛴 시각): 공백 길이만큼 뒤로 밀어 해석하고 `notice: NONEXISTENT_LOCAL_TIME`을 붙입니다.
2. **절기 비교용 시각:** 절대 시각을 UTC+8 벽시계 시각으로 바꿔 lunar-python에 넣습니다. lunar-python의 절기 시각이 UTC+8 기준이기 때문입니다(07 §6, 2024 입춘 실행 확인). 이 값으로 **연주·월주**를 정합니다.
3. **시주·일주용 보정 시각:** `절대 시각 + 경도 × 4분`입니다.
   * 경도가 없으면 대표 경도를 씁니다(§4.2).
   * `Asia/Seoul`의 대표 경도는 127.5°이므로 결과는 `UTC + 8:30`, 즉 표준시 -30분과 같습니다(D5).
4. **자시 처리:** 보정 시각 기준 23:00~00:59는 **다음 날 일주 + 자시**로 계산합니다(자시 통합, D6). lunar-python에서는 `EightChar.setSect(1)`입니다. 자시 출생에는 `notice: ZI_HOUR_NEXT_DAY`를 붙입니다.

### 4.2. 대표 경도
| 시간대 | 대표 경도 | 근거 |
| --- | --- | --- |
| `Asia/Seoul` | 127.5° | 국내 만세력 관례 (D5) |
| 그 밖의 모든 시간대 | 출생 시점 표준 오프셋의 표준 자오선 (오프셋 시간 × 15°) | 보정 0. 나라별 관례 조사는 해당 언어권 사용자의 도시 단위 출생지 입력(D29)으로 보완 |

* 서머타임은 표준 자오선 계산에 넣지 않습니다. 예를 들어 서머타임 중인 UTC-4는 표준 오프셋 UTC-5 → 75°W로 봅니다.

### 4.3. 절입 전후 안내
절입 시각 ±120분 안에 태어났으면 `notice: NEAR_SOLAR_TERM`을 붙입니다(D32). 이때 월주(와 입춘이면 연주까지)가 입력 오차에 민감합니다. 시간 모름이면서 출생일이 절입일이면, 월주를 그날 정오 기준으로 정하고 같은 notice를 붙입니다.

### 4.4. 데일리의 "오늘"
데일리와 월간 캘린더의 날짜는 **요청에 담긴 사용자의 현재 시간대의 달력 날짜(자정 기준)**입니다(D30). 그날의 일진은 그 날짜의 정오(현지 시각) 기준 간지로 정합니다. 날짜 경계 근처의 모호함을 없애기 위해서입니다.

## 5. 원국 계산 (`chart`)

### 5.1. 사주팔자
* 연주·월주: §4.1-2의 절기 비교용 시각으로 정합니다.
* 일주·시주: §4.1-3·4의 보정 시각으로 정합니다.
* 시간 모름: 시주를 비우고 `notice: TIME_UNKNOWN`을 붙입니다. 시주에 의존하는 값(시주 십성·12운성, 시지 관련 신살·합충)은 계산하지 않습니다.

### 5.2. 십성·지장간·12운성
* 십성: 일간 기준으로 각 천간과 각 지지 정기의 십성을 냅니다.
* 지장간: lunar-python의 목록을 쓰며 **첫 항목이 정기**입니다(2026-10-10 확인. 예: 巳 = 丙·庚·戊). 지장간마다 십성도 냅니다.
* 12운성: 일간 기준으로 각 지지의 12운성을 냅니다.

### 5.3. 대운·세운
* 대운 방향: 연간이 양이면서 남성이거나, 연간이 음이면서 여성이면 순행, 그 밖은 역행입니다.
* 대운 시작 나이: lunar-python `getYun(gender, sect=1)`을 씁니다(3일 = 1년, 1일 = 4개월, 1시진 = 10일). `getDaYun()`의 첫 항목은 대운 시작 전 구간(간지 없음)이므로 표에서 뺍니다.
* 대운 표: 10개 구간. 각 구간에 간지, 시작 나이(만 나이와 한국식 나이 둘 다), 천간·지지 십성, 12운성을 넣습니다.
* 세운 표: 현재 대운 구간의 10년. 각 해에 간지, 십성, 원국 지지와의 합·충을 넣습니다.
* 시간 모름: 대운 시작 나이는 시진 정보가 없어 오차가 생기므로 `notice: DAYUN_START_APPROXIMATE`를 붙이고, 그날 정오 기준으로 계산합니다.

### 5.4. 신살 (MVP 범위)
| 신살 | 기준 | 판정 |
| --- | --- | --- |
| 천을귀인 | 일간 | `CHEONEUL_GWIIN[일간]`에 해당하는 지지 (07 §5) |
| 도화 | 연지와 일지 각각 | 삼합 그룹의 도화 지지: 寅午戌→卯, 申子辰→酉, 巳酉丑→午, 亥卯未→子 |
| 역마 | 연지와 일지 각각 | 寅午戌→申, 申子辰→寅, 巳酉丑→亥, 亥卯未→巳 |
| 화개 | 연지와 일지 각각 | 寅午戌→戌, 申子辰→辰, 巳酉丑→丑, 亥卯未→未 |
| 양인 | 일간(양간만) | 甲→卯, 丙→午, 戊→午, 庚→酉, 壬→子 |
| 공망 | 일주 | 일주가 속한 순(旬)의 공망 두 지지 (lunar-python `getDayXunKong`) |

* 원국 표에는 원국 안에 실제로 있는 신살만 표시합니다.
* 데일리에서는 **오늘 지지가 내 신살 지지에 해당하는지**로 "발동"을 판정합니다(D13).

## 6. 강약과 용신

### 6.1. 신강·신약 (`rules/strength.py`)
* **자리 가중치** (07 §3.1 원안): 월지 3, 그 밖의 지지 1.5, 천간 1. 일간 자신은 뺍니다. 시간 모름이면 시주 두 자리를 빼고 계산합니다.
* **지지의 오행 배분:** 지지 가중치를 지장간 비율로 나눕니다.
  * 지장간 3개: 정기 0.6 / 중기 0.3 / 여기 0.1
  * 지장간 2개: 정기 0.7 / 나머지 0.3
  * 지장간 1개: 1.0
* **점수:** 일간을 돕는 오행(비겁 + 인성)의 가중 합 ÷ 전체 가중 합 × 100.
* **등급:** 무작위 출생 2만 건(1900~2099년 균등, 시각 균등)의 점수 분포에서 15·40·60·85 백분위를 경계로 5등급(`VERY_WEAK`, `WEAK`, `NEUTRAL`, `STRONG`, `VERY_STRONG`)으로 나눕니다. 보정 스크립트(`tools/calibrate_strength.py`)의 결과를 상수로 고정하고, 상수가 바뀌면 `ruleset_version`을 올립니다.
* 오행별 가중 합(오행 분포)도 함께 반환합니다. "나의 사주" Pro 화면의 오행 분포가 이 값입니다.

### 6.2. 용신·희신·기신 (`rules/yongsin.py`) — D7, D32
판정 순서는 다음과 같습니다.
1. **조후:** 월지가 巳·午·未이고 화(火) 비중이 기준 이상이거나, 월지가 亥·子·丑이고 수(水) 비중이 기준 이상이면 조후로 정합니다.
   * 기준: 같은 계절에 태어난 무작위 표본에서 해당 오행 비중의 **상위 40%** 경계값입니다. §6.1의 보정 스크립트가 함께 산출합니다.
   * 용신은 `JOHU_YONGSIN[일간][월지]`의 첫 글자의 오행이며, 방식은 `JOHU`로 기록합니다.
2. **중화:** 강약 등급이 `NEUTRAL`이면 조후표의 첫 글자를 쓰고, 방식은 `JOHU_NEUTRAL`로 기록합니다.
3. **억부:** 그 밖에는 억부로 정하고, 방식은 `EOKBU`로 기록합니다.
   * `WEAK` 이하: 인성 오행이 용신입니다.
   * `STRONG` 이상: 식상·재성·관성 오행 중 §6.1 오행 분포에서 가장 약한 오행이 용신입니다. 동점이면 식상 → 재성 → 관성 순입니다.
4. **희신:** 용신을 생(生)하는 오행입니다.
5. **기신:** 용신을 극(剋)하는 오행입니다.
6. **통관 오행:** 기신과 용신 사이를 잇는 오행(기신이 생하고, 용신을 생하는 오행)입니다. 정의상 희신과 같은 오행이며, §7.1에서 씁니다.

**근거(`evidence`):**
* `JOHU`·`JOHU_NEUTRAL`: `gungtong-bogam/johu_evidence#<일간>.<월지>`
* `EOKBU`: `gungtong-bogam/five_elements#balance_principle`과 강약 점수

## 7. 데일리 규칙

### 7.1. 날의 성격 (`rules/day_kind.py`) — D19
오늘 일진의 천간 오행과 지지(정기) 오행으로 판정합니다. 위에서부터 처음 해당하는 것이 그날의 성격입니다.

| 순위 | 성격 | 조건 |
| --- | --- | --- |
| 1 | `GWIIN_DAY` 귀인의 날 | 오늘 지지가 내 천을귀인 지지 |
| 2 | `YONGSIN_DAY` 용신의 날 | 일진 오행에 용신이 있고 기신이 없음 |
| 3 | `GISIN_DAY` 기신의 날 | 일진 오행에 기신이 있음 |
| 4 | `ORDINARY_DAY` 평범한 날 | 그 밖 |

* 용신의 날 문구는 "좋은 날"로 강조합니다(D20). 엔진은 `emphasis: POSITIVE` 매개변수만 붙입니다.

### 7.2. 행운 컬러 (`rules/color.py`) — D14, D19
| 날의 성격 | 오행 |
| --- | --- |
| 귀인의 날 | 용신 |
| 용신의 날 | 용신 |
| 기신의 날 | 통관 오행 |
| 평범한 날 | 용신 |

* 엔진은 **오행과 역할**(용신·통관)만 반환합니다. 색 이름과 색 값은 디자인 시스템(06 §2)의 오행 팔레트로 앱이 정합니다. 목=세이지 그린, 화=코랄 핑크, 토=웜 샌드 베이지, 금=오프화이트·라이트 그레이, 수=딥 네이비·뮤트 블루입니다.
* 근거: `gungtong-bogam/five_elements#color`. 금은 원문 근거가 없다는 `note`를 그대로 전달합니다.

### 7.3. 행운 방향 (`rules/direction.py`) — D19
8방위를 쓰고, 방위의 오행은 후천팔괘로 정합니다: 북=수, 북동=토, 동=목, 남동=목, 남=화, 남서=토, 서=금, 북서=금.

| 날의 성격 | 방위 |
| --- | --- |
| 귀인의 날 | 오늘 지지(귀인 지지)의 방위 (지지 방위표 §7.3.1) |
| 용신의 날 | 용신 오행의 대표 방위 |
| 기신의 날 | 통관 오행의 대표 방위 |
| 평범한 날 | 그날의 길신 방위(희신·복신·재신·양귀·음귀, lunar-python) 중 오행이 용신인 첫 방위 → 없으면 희신인 첫 방위 → 없으면 용신 대표 방위 |

* **오행 대표 방위:** 수=북, 화=남, 목=동, 금=서.
* **토의 방위:** 토는 대표 방위가 없으므로 북동·남서 중에서 고릅니다. 오늘 지지가 丑·寅(북동 쪽 지지)과 충이면 남서, 未·申(남서 쪽 지지)과 충이면 북동, 그 밖에는 북동입니다.
* **§7.3.1 지지 방위표:** 子=북, 丑·寅=북동, 卯=동, 辰·巳=남동, 午=남, 未·申=남서, 酉=서, 戌·亥=북서.
* 근거: `five_elements#direction`, 그리고 적용한 규칙(`day_kind/*`)입니다.

### 7.4. 행운의 숫자 (`rules/number.py`) — D25 (승인 대기)
* 오행은 §7.2와 같은 방식으로 정합니다.
* 숫자는 그 오행의 하도 수 한 쌍(수 1·6, 화 2·7, 목 3·8, 금 4·9, 토 5·10) 중에서 고릅니다. 일진 천간이 양간이면 홀수, 음간이면 짝수입니다.
* 근거: `five_elements#number`(생수 1~5)와 하도 성수입니다.

### 7.5. 집중하기 좋은 시간 (`rules/focus_time.py`) — D21
1. **후보:** 진시~술시 7개 시진입니다. 시진 경계는 사용자의 현재 시간대에서 보정 시각을 거꾸로 적용해 정합니다. 서울은 07:30~09:29(진시) … 19:30~21:29(술시)입니다.
2. **제외:** 시진 지지가 원국 지지(시간 모름이면 시지 제외) 중 하나와 충이면 뺍니다.
3. **점수:** 귀인 시진(시진 지지가 내 천을귀인) +3, 시진 천간 또는 지지 오행이 용신 +2, 희신 +1, 시진 지지가 원국 지지와 육합 +1.
4. **동점:** 황도길시(lunar-python `getTianShenLuck() == 吉`)를 먼저 둡니다. 그래도 같으면 이른 시진이 먼저입니다.
5. **결과:** 점수가 가장 높은 시진 1개입니다. 두 번째 시진이 같은 점수면 2개까지 냅니다. 모든 후보가 제외되면 제외 전 후보 중 황도길시 첫 시진을 내고 `notice: FOCUS_TIME_FALLBACK`을 붙입니다.

### 7.6. 합·충·형 (`rules/relations.py`) — 07 §3.2·§4.1
* **판정 대상:** 오늘 일진의 천간·지지 대 원국의 천간·지지입니다(원국 내부 관계는 "나의 사주" 표에서 따로 냅니다).
* **종류:** 천간합(5종), 지지육합(6종), 지지충(6종), 지지형(寅巳申, 丑戌未, 子卯, 자형 辰·午·酉·亥)입니다.
* **탐합망충:** 오늘 지지가 원국의 한 지지와 합을 이루면서 **다른** 원국 지지와 충을 이루면, 합만 남기고 충을 무효로 둡니다(07 §4.1). 무효가 된 충도 근거에 `suppressed_by: HAP`으로 남깁니다.
* **합화 오행 변화:** MVP에서는 합화로 오행을 바꾸지 않습니다. 합의 존재만 판정에 씁니다. "인접" 조건(07 §3.2)은 원국 내부의 합화 판정에만 의미가 있어 Phase 2로 미룹니다.
* 매핑 키는 `frozenset`을 씁니다(07 §5).

### 7.7. 해시태그 (`rules/tags.py`) — 07 §4.3
**MVP 태그 목록** (키는 콘텐츠 모듈이 언어별 이름으로 바꿉니다):

| 그룹 (우선순위) | 태그 키 | 조건 | 길흉 |
| --- | --- | --- | --- |
| 1. 합·충 | `tag.big_change` (#대변화의날) | 오늘 지지가 원국 **일지** 또는 **월지**와 충 (탐합망충 반영 후) | 흉 |
| | `tag.clash` (#충돌주의) | 오늘 지지가 원국의 다른 지지와 충 | 흉 |
| | `tag.harmony` (#합의날) | 천간합 또는 지지육합 성립 | 길 |
| 2. 십성 쏠림 | `tag.ten_god_rush.<그룹>` (#비겁다발·#식상다발·#재성다발·#관성다발·#인성다발) | 오늘 천간과 지지 정기의 십성 그룹이 같고, 그 그룹이 원국에도 2개 이상 있음 | 그룹별 (관성=흉, 재성·인성·식상=길, 비겁=중립) |
| 3. 신살 | `tag.cheoneul_gwiin`·`tag.dohwa`·`tag.yeokma`·`tag.hwagae`·`tag.gongmang` | §5.4의 신살 지지가 오늘 지지에 해당 (발동) | 귀인·도화=길, 역마·화개=중립, 공망=흉 |
| 보조 | `tag.yongsin_day`·`tag.gwiin_day` | §7.1 날의 성격 | 길 |

* **선택:** 그룹 우선순위로 정렬한 뒤 앞의 1~2개를 고릅니다. 같은 그룹 안의 동점은 07 §4.3의 추길피흉 규칙(흉 우선 → 일간을 극하는 기운 우선 → 재성·도화 우선)을 따릅니다.
* 보조 태그는 1~3그룹에 해당하는 태그가 없을 때만 씁니다.
* 일기에 저장되는 태그는 **이 응답의 태그 키 전체 목록**입니다. 대표 1~2개는 화면 표시용입니다. 회고 기능에서 같은 특성의 날을 넓게 찾을 수 있게 하려는 것입니다.

### 7.8. 총운·가이드 질문 메시지 (`rules/messages.py`) — D22, D24
* **총운:** 메시지 키는 `fortune.<날의 성격>.<오늘 천간의 십성 그룹>`입니다(4 × 5 = 20 조합). 대표 태그가 있으면 `fortune.tag.<태그 키>`를 보조 문장으로 붙입니다.
* **가이드 질문:** 메시지 키는 `guide.<대표 태그 키>`, 대표 태그가 없으면 `guide.ten_god.<오늘 천간의 십성 그룹>`입니다. 키마다 콘텐츠 모듈에 문장을 여러 개 두고, Go 서버가 날짜 기반으로 하나를 고릅니다(엔진은 관여하지 않음).
* 매개변수: 오행, 십성, 날의 성격, 강조(`emphasis`)입니다.

## 8. 월간 캘린더 (`rules/calendar_luck.py`)
날짜마다 아래 점수를 더합니다.

| 항목 | 점수 |
| --- | --- |
| 귀인의 날 | +2 |
| 용신의 날 | +2 |
| 천간합 또는 지지육합 (원국과) | +1 |
| 기신의 날 | -1 |
| 지지충 (탐합망충 반영 후, 일지·월지와) | -2 |
| 지지충 (그 밖의 지지와) | -1 |
| 지지형 | -1 |

* **수준:** +2 이상 `GOOD`, -2 이하 `CAUTION`, 그 밖은 `NEUTRAL`입니다. 앱은 06 디자인 시스템의 색 점으로 표시합니다. 색 규칙은 디자인 단계에서 정합니다.
* **함께 반환:** 날짜별 음력 날짜(윤달 여부 포함), 절기 이름과 입절 시각(해당 날짜만), 일진 간지, 날의 성격, 대표 태그 키.
* 점수 구성은 근거로 함께 반환합니다(Pro 화면에서 "왜 좋은 날인가"를 보여주기 위해).

## 9. gRPC 인터페이스

```proto
syntax = "proto3";
package myungri.engine.v1;

service MyungriEngine {
  rpc GetChart(ChartRequest)         returns (ChartResponse);
  rpc GetDaily(DailyRequest)         returns (DailyResponse);
  rpc GetMonthCalendar(MonthRequest) returns (MonthResponse);
}

message BirthInfo {
  CalendarType calendar     = 1;
  bool         is_leap_month = 2;
  LocalDate    date         = 3;
  optional LocalTime time   = 4;
  Gender       gender       = 5;
  string       timezone     = 6;
  optional double longitude = 7;
}

message ChartRequest  { BirthInfo birth = 1; LocalDate as_of = 2; }   // as_of: 세운 기준 연도용
message DailyRequest  { BirthInfo birth = 1; LocalDate date = 2; string current_timezone = 3; }
message MonthRequest  { BirthInfo birth = 1; int32 year = 2; int32 month = 3; string current_timezone = 4; }

message Judgment {
  string message_key           = 1;
  map<string, Param> params    = 2;
  repeated Evidence evidence   = 3;
}
message Evidence {
  string rule_id    = 1;
  string source_ref = 2;
  map<string, string> detail = 3;   // 예: 점수 구성, suppressed_by
}
message Notice { NoticeCode code = 1; map<string, string> detail = 2; }

message ResponseMeta {
  string engine_version  = 1;
  string ruleset_version = 2;
  repeated Notice notices = 3;
}
```

* `ChartResponse`: 네 기둥(시간 모름이면 시주 없음), 십성, 지장간과 지장간 십성, 12운성, 신살, 공망, 오행 분포, 강약 점수와 등급, 용신·희신·기신과 판정 방식(`Judgment`), 대운 표, 세운 표, `ResponseMeta`.
* `DailyResponse`: 일진, 날의 성격, 컬러·방향·숫자·집중 시간(각각 `Judgment` + 원본 값), 합충형 목록, 태그(대표 + 전체), 총운·가이드 질문 `Judgment`, `ResponseMeta`.
* `MonthResponse`: 날짜별 항목(§8) 배열, `ResponseMeta`.
* 천간·지지·오행·십성·12운성·신살·방위·날의 성격은 모두 enum입니다.
* 오류: 잘못된 입력은 `INVALID_ARGUMENT`, 지원 범위 밖은 `OUT_OF_RANGE`, 그 밖의 예외는 `INTERNAL`입니다. 계산이 되는 민감 상황은 오류가 아니라 `notices`입니다(D32).
* `.proto`는 이 저장소의 `proto/`에 두고, Go 서버와 공유합니다. 변경은 `buf breaking`으로 검사합니다.

## 10. 메시지 키 규칙
* 형식: `<영역>.<세부>[.<세부>]`, 소문자 스네이크 케이스. 예: `direction.day_kind.yongsin`, `tag.ten_god_rush.siksang`.
* 엔진의 모든 메시지 키 목록은 `constants/message_keys.py` 한 곳에 둡니다. 테스트에서 이 목록을 내보내고, Go 콘텐츠 모듈의 시드 파일이 모든 키를 3개 언어(D28)로 갖고 있는지 Go 쪽 테스트에서 검사할 수 있게 합니다.

## 11. 근거(`source_ref`) 규칙
* 형식: `<자료 디렉터리>/<파일 이름(확장자 제외)>#<키 경로>`. 예: `gungtong-bogam/johu_evidence#甲.子`, `gungtong-bogam/five_elements#direction`.
* 근거 데이터 파일은 엔진 패키지에 함께 넣고, 시작할 때 한 번 읽어 검증합니다. 키가 없으면 엔진이 시작되지 않습니다.

## 12. 버전 관리
* `engine_version`: 엔진 패키지 버전입니다.
* `ruleset_version`: 규칙·상수·근거 데이터가 바뀌어 출력이 달라질 때 올립니다(예: `2026.10.0`). 회귀 스냅샷(§13.7)이 실패하면 이 값을 올려야 테스트가 통과하게 합니다.
* Go 서버는 일기 저장 시 태그와 함께 `ruleset_version`을 기록하고, 캐시 키에 넣습니다(D31).
