# MVP 화면 목록(IA) Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** IA 계약 `docs/ia/screens.json`과 그 검사기, 관련 결정·로드맵·계약 목록·제품 지도를 한 PR로 `main`에 넣습니다.

**Architecture:** 검사는 기존 `tools/docs-check/docs_check.py`에 `check_ia`로 추가합니다(`python3 -I`는 스크립트 디렉터리를 `sys.path`에 넣지 않으므로 별도 모듈로 나누지 않음). 계약 데이터는 spec §4·§6·§7을 JSON으로 옮기고, 검사기를 통과시키는 것으로 검증합니다. 제품 지도는 객체 형식의 `screens`를 읽게 고칩니다.

**Tech Stack:** Python 3.13 표준 라이브러리(unittest, json, re), GitHub Actions(`ci-gate.yml`)

**Spec:** `docs/specs/2026-10-11-ia-design.md`

## Global Constraints

* 작업 위치: worktree `/Users/bran/personal/myungli-diary-root`, 브랜치 `root/ia`(`origin/main`에서 `--no-track`로 만듦). push는 `git push -u origin root/ia`.
* 모든 변경은 PR → `ci-gate` → merge commit(D44). `main`에 직접 push하지 않습니다.
* 문서 문체: 한국어 경어체(합니다체), 번역투·슬롭 패턴 금지(`docs/identity/README.md`).
* Python은 `python3 -I`로 실행하고 표준 라이브러리만 씁니다.
* 화면·컴포넌트 id: `^[a-z0-9]+(-[a-z0-9]+)*$`. 슬롯 id: `^[a-z0-9]+(-[a-z0-9]+)*(\.[a-z0-9]+(-[a-z0-9]+)*){2,}$`이고 `<화면 id>.`로 시작.
* 허용 값: `presentation` ∈ {page, half-sheet, full-sheet, system}, `auth` ∈ {guest, member, any}, `depths` ⊆ {surface, explain, evidence}, `states[].id` ∈ {loading, empty, error, offline, draft, time-unknown, out-of-range}, `slots[].source` ∈ {content, ui}.
* 검사 메시지 형식: `docs/ia/screens.json: <이유>`(전체) 또는 `docs/ia/screens.json [<화면 id>]: <이유>`(화면별). 기존 `check_artifacts`와 같은 모양입니다.
* app·server 착수 notice는 이번에 보내지 않습니다(수익화 사이클 뒤). writing·design notice만 보냅니다.

## Review Focus

1. 필드 타입이 틀린 입력(`slots`가 배열이 아님, `version`이 `true`, 항목이 객체가 아님) → 예외 없이 문제 메시지로 보고해야 합니다.
2. 화면 id가 다른 화면 id의 앞부분인 경우(`today`와 `today-x`) → 슬롯 접두 검사는 `"<id>."` 전체로 비교해야 합니다.
3. 필수 키가 빠진 화면 → `KeyError` 없이 빠진 키 이름을 보고해야 합니다.
4. 서로 다른 화면에 같은 슬롯 id → 중복으로 보고해야 합니다.
5. `screens.json`이 없는 저장소 → IA 검사는 아무것도 보고하지 않아야 합니다(서브 프로젝트 브랜치가 깨지지 않게).
