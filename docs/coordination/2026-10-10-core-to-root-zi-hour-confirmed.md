# 자시 통합(D6)을 기준 앱 두 곳의 기본 동작으로 확인했고, 만세력 골든 테스트를 추가함

## 무엇이 필요한가 / 무엇을 했는가
* **자시 기본 동작 확인:** 포스텔러 만세력과 사공만세력 모두 기본 설정(야자시 옵션 꺼짐)에서 보정 시각 23시대 출생을 **다음 날 일주 + 子시**로 계산합니다. D6(자시 통합)과 같으므로 D6은 그대로 둡니다. 07 §2.3에 "확인 완료(2026-10-10, 포스텔러 만세력·사공만세력)"를 적었습니다.
  * 포스텔러: 추가 조회 1건(양력 2000-05-15 23:45 남, 서울 → 보정 23:13)에서 4주가 庚辰·辛巳·甲戌·甲子입니다. 일주 甲戌은 5/16 일주(5/15는 癸酉)이므로, 보정 후 같은 날 23시대에 다음 날 일주로 넘어가는 것을 직접 확인했습니다. `dst_gap_1987`(보정 5/9 23:58 → 일주 己未, 시주 甲子)도 같은 결과입니다. 골든 사례 중 자시 경계 사례(23:29·23:30)는 서울 -32분 자동 보정 때문에 亥시로 내려가 근거가 되지 못했습니다.
  * 사공만세력: `zi_2329`·`zi_2330`(보정 23:01·23:02)에서 일주가 甲戌(다음 날)이고 시주가 甲子입니다. 야자시 옵션을 켰을 때의 동작은 확인하지 않았습니다(MVP에 옵션이 없어 필요 없음).
* **만세력 골든 테스트:** `core/tests/golden/test_reference_apps.py`가 경계 사례 30건의 사주팔자와 대운 시작 나이를 두 앱의 기본 설정 결과와 대조합니다. 허용하는 차이는 `core/tests/golden/fixtures/reference_known_differences.json`에 건별 사유와 채택 근거와 함께 있습니다. 채택 근거는 `core/docs/decisions.md` C1~C5에 있습니다.
  * 사주팔자: 20건은 엔진·두 앱이 모두 같습니다. 10건(13필드)이 다르며, 엔진이 두 앱 모두와 다른 것은 2건(`kst830_1955`·`dst_1956` 시주, 경도 보정 2분 차이로 경계 정각)뿐입니다.
  * 대운 시작 나이: 15건이 모두 같습니다. 12건은 포스텔러만(반올림·0을 10으로 표기), 3건은 사공만세력만 다릅니다. 사공만세력 3건 중 `gyeongchip_after`는 절입 비교 기준, `pre1912_1910`은 진태양시 보정 시각(추정)이 원인이고, `normal_1999`는 엔진 `getYun(sect=1)`이 시진(10일) 단위로 세어 정밀값 7.99년을 8로 올린 결과입니다(spec 5.3대로 유지, C5).

## 왜
spec 1.2-2·13.3과 D10에 따라 해석 관례를 기준 앱과 대조해야 하고, D6은 "기준 앱의 기본 동작으로 최종 확인"을 조건으로 두었습니다.

## 영향
* 루트 결정 변경 요청은 없습니다. D5·D6은 그대로입니다.
* 다른 서브 프로젝트의 계약 변경은 없습니다.
* 참고(app): 경도 보정 2분과 진태양시 차이 때문에 사용자가 다른 만세력 앱과 시주가 다르다고 문의할 수 있습니다. 차이는 시주 경계 정각 몇 분 안쪽 출생에서만 생깁니다. 앱 안의 계산 기준 안내(07 §2.3)에 "동경 127.5° 기준 -30분 보정, 진태양시 미적용"을 함께 적을지는 root가 판단합니다.
