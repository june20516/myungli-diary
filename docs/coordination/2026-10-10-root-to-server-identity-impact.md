# 브랜드 기반 결정이 server 설계(S1)에 주는 영향

## 무엇이 필요한가
S1 설계를 시작할 때 아래를 범위에 넣어 주세요. 지금 `server/CLAUDE.md`에는 반영되어 있지 않으니, server 세션이 S1을 시작하면서 "범위"와 "현재 상태"를 고쳐 주세요.

1. **호칭 (D36):** 프로필에 호칭(앱이 사용자를 부를 말)을 필수 값으로 저장합니다. 실명이 아니어도 됩니다.
2. **호칭·조사 처리 (D36):** 콘텐츠 모듈(D27)의 템플릿 렌더러가 호칭 뒤 접미사("님"·"さん")와 조사(은/는·이/가·을/를·와/과)를 처리해야 합니다. 규칙은 writing 작업 단위가 W0에서 정해 계약("호칭·조사 처리 규칙")으로 제공합니다.
3. **문장 유형과 반응 (D40):** 콘텐츠 문장은 유형(`advice`·`state`·`care`) 축을 가집니다.
   * MVP: 같은 슬롯 안에서 유형을 순환해 보여주고, 문장에 대한 사용자 반응(좋아요)을 저장합니다.
   * Phase 2: 반응에 맞춰 유형을 고르는 적응형 선택. 반응은 같은 날 종류(D19) 안에서 유형끼리 비교합니다.
   * W1 콘텐츠 분량이 유형 수만큼 늘어납니다(약 3배).
4. **슬롯 명세·검사기:** 콘텐츠 시드 파일의 형식과 시드 CI는 writing이 제공하는 슬롯 명세와 검사기(W0)를 따릅니다.
5. **용어 (D37):** 정보 깊이는 Easy/Pro 대신 `surface`·`explain`·`evidence`로 부릅니다. API 필드 이름에도 이 이름을 씁니다.

## 왜
브랜드 기반 spec(`docs/specs/2026-10-10-brand-foundation-design.md`) 승인으로 D36~D40이 정해졌습니다. 정체성 기준은 `docs/identity/README.md`입니다.

## 영향
server 범위가 넓어집니다(프로필 필드, 콘텐츠 모듈의 렌더링 규칙, 반응 저장). 기존 계약은 깨지지 않습니다. 새 계약 "호칭·조사 처리 규칙", "슬롯 명세"는 W0에서 생깁니다.
