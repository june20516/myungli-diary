# 작업 규약 경과와 세부 동작

[`workflow.md`](workflow.md)의 지금 규칙 뒤에 있는 경위와 도구의 세부 동작입니다. 지금 규칙은 workflow.md가 기준입니다(D131).

## §6.1 drift Issue가 닫히는 세부 동작

drift Issue는 아래처럼 `drift-close`가 닫습니다. `Closes`로 닫으면 아직 따라잡지 않은 더해진 원인이 함께 사라집니다(PR #512가 원인 PR #511 몫을 남긴 채 #480을 닫은 일, 2026-10-23). 주는 쪽이 같은 PR 안에서 고쳐 다음 실행의 drift가 통과하면 `drift-report`가 그 Issue를 닫습니다. `main` push에서는 drift를 돌리지 않습니다(결과를 판정에도 Issue에도 쓰지 않으므로). `main` push에서 그 단위 검사가 통과하면 `ci-gate`(`drift-close` job)가 그 단위 앞 drift Issue를 닫습니다. 그 커밋에서 통과했다는 것이 곧 그 커밋의 계약을 모두 따라잡았다는 뜻이기 때문입니다. 단, 원인 PR(제목과 더해진 원인 모두)이 그 커밋에 들어 있는 Issue만 닫습니다(원인 PR이 열린 채 다른 PR이 먼저 병합되거나, 예전 실행을 다시 돌린 경우를 거릅니다). 병합 없이 닫힌 원인 PR은 따라잡을 것이 없으므로 셈에서 빼고, 원인 PR이 모두 병합 없이 닫혔으면 이후 `main`에서 그 단위 검사가 통과할 때 not planned로 닫습니다(그 단위 검사가 돌지 않으면 남습니다). 주는 쪽이 같은 PR 안에서 고친 경우 `drift-report`는 그 PR이 연 Issue를 닫되, 다른 원인이 더해진 Issue는 남깁니다.

## §6.1 쌓아서 병합하기

예전에는 쌓아서 함께 병합하는 것이 기본이었습니다(예: IA v2 #133 → #138 → #149).

## §8 운영 확장 메모(2026-10-10 작성, 2026-11-14 옮김)

iOS 빌드, 배포 파이프라인처럼 이미 도입된 항목이 섞여 있어 지금 규칙에서 뺐습니다. 아직 도입하지 않은 항목(merge queue, 서비스 간 통합 테스트, Dependabot, `main` 보호 규칙)을 도입할 때 지금 규칙에 적습니다.

지금은 도입하지 않고, 아래 시점에 도입합니다(협업 워크플로 spec §4.2).

| 항목 | 도입 기준 |
| --- | --- |
| merge queue | 동시에 열린 PR끼리 병합 순서 충돌이 잦아질 때 |
| 서비스 간 통합 테스트(docker compose로 server ↔ core gRPC 실호출) | I1 시점에 `ci-gate`에 추가 |
| 배포 파이프라인(환경별 시크릿, 접두어 태그 릴리스) | 배포 플랫폼 결정 뒤(S1) |
| iOS 빌드 | A1·I4. 로컬 Mac 또는 자체 러너. 호스티드 macOS는 분 단위 비용 10배 |
| 의존성 자동 갱신(Dependabot) | MVP 안정화 뒤 |
| `main` 보호 규칙 강제 | 공개 전환(D74)으로 조건이 됐습니다. `ci-gate`를 필수 검사로 지정할지 사용자가 정합니다 |
