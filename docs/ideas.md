# 아이디어 함

기능, 화면, 경험, 수익 모델 등 제품 아이디어를 받는 곳입니다. 설계 근거는 [M0 spec](specs/2026-10-11-m0-monetization-design.md) §3.3에 있고, `tools/docs-check`가 형식을 검사하며, 제품 지도의 "아이디어" 탭이 이 표를 흐름 보드로 보여줍니다.

* 고치는 쪽은 지휘 세션입니다. 아이디어가 들어오면 그 자리에서 결정하지 않고 `대기`로 적습니다.
* 지휘 세션은 기획 spec을 시작할 때 `대기`를 훑어 관련 있는 것을 `검토 <그 spec 경로>`로 묶습니다. [수익화 사이클](business/README.md)도 같은 방식으로 가져갑니다.
* `id`는 `I1`부터 차례로 붙이고 다시 쓰지 않습니다. 칸 안에 `|`를 쓰려면 `\|`로 적습니다.

| 열 | 값 |
| --- | --- |
| 출처 | `사용자`, `조사`, `Issue #N` |
| 범위 | `MVP`, `Phase 2`, `미정` — 언제 넣을지에 대한 지금의 판단 |
| 수익 | `무관`, `무료`, `유료 후보`, `미정` — 수익화 사이클이 가져갈지 정하는 열 |
| 상태 | `대기`, `검토 <저장소 기준 문서 경로>`, `채택 Dn`, `보류`(메모에 이유), `기각`(메모에 이유) |
