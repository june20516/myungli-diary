# 출시 때 결제를 붙이는가

* 작성: 지휘 세션, 2026-10-11
* 상태: 반영 완료
* 관련 결정: D12·D23·D52, 결론 D53·D54
* 절차: [수익화 결정 체계](../README.md)

## 1. 질문

MVP 출시 때 결제를 붙이는가. 붙인다면 어떤 작은 유료 기능 하나를 붙이는가.

바뀔 수 있는 범위:
* IA: 결제 화면, 유료 표시, 설정의 구독 관리
* S1: 권한(entitlement)과 영수증 검증
* A1: 인앱결제(IAP) 연동
* writing: 결제 안내 문구
* design: 유료 배지

함께 다룰 아이디어: 아이디어 함이 비어 있어, 조사에서 나온 유료 후보(§2 끝)를 함에 넣고 이 사이클에서 다룹니다.

3. LLM 기능은 횟수로 제한합니다(질문 묶음, 일일 한도). D12·D23과 그대로 맞습니다.

유료 후보는 아이디어 함에 I1~I6으로 넣었습니다(출처 `조사`).

## 3. 선택지

LLM 기능은 D24에 따라 Phase 2이고, 다른 날 전체 풀이는 D47⑥에 따라 MVP에서 뺐습니다. 그래서 MVP 안에서 바로 팔 수 있는 작은 유료 기능 후보가 마땅치 않다는 점이 선택지를 가릅니다.

### (가) 전부 무료로 출시, 결제는 Phase 2
* 기준 1: 가장 좋음. 첫 심사와 출시 준비가 가장 단순합니다.
* 기준 2: 약함. 실제 결제가 없어 "돈을 내는 사람이 있는가"는 Phase 2까지 모릅니다.
* 기준 3: 맞음.
* 범위 영향: 없음. 결제를 붙일 때 권한 모델을 새로 넣으면서 스키마를 바꿔야 합니다.

### (나) 출시 때 작은 유료 기능 하나
* 후보: I3 기간 리포트(LLM 없이 템플릿으로 가능, 단 D47⑥ 개정 필요) 또는 I1 오늘에 대해 묻기(D24 개정, LLM을 MVP로 당김).
* 기준 1: 핵심 경험은 무료로 두므로 크게 해치지 않지만, 출시가 늦어집니다.
* 기준 2: 가장 강함. 출시 첫날부터 실제 결제를 봅니다.
* 기준 3: 맞음(횟수·기능 단위).
* 범위 영향: 큼. IA에 페이월·구매 복원·구독 관리 화면 추가, S1에 권한과 영수증 검증(RevenueCat webhook), A1에 결제 연동과 페이월, writing에 결제 안내 문구, design에 유료 배지. 고른 후보에 따라 D24나 D47⑥ 개정. 출시 전 행정 요건 완료 필요.

### (다) 무료로 출시하고 권한 모델만 S1에 넣은 뒤, 출시 직후 결제 켜기 (권장)
* S1에 권한 테이블·기능 게이트·webhook 자리를 둡니다. 결제 연동은 RevenueCat을 기본안으로 합니다.
* 출시 때 유료 후보의 수요를 프록시 지표(proxy metric)로 봅니다. 예: 달력에서 다음 달로 넘겨 보는 횟수(I3 기간 리포트), 일기 편수와 태그 모아보기 사용(I2 회고 요약), evidence 깊이까지 펼친 비율(I1 질문권). 이 지표로 다음 사이클에서 켤 기능 하나를 고릅니다.
* 기준 1: 좋음. 출시 범위와 첫 심사는 (가)와 같습니다.
* 기준 2: (가)보다 빠름. 출시 직후 1~2주 안에 실제 결제를 켤 수 있습니다(추정).
* 기준 3: 맞음.
* 범위 영향: 작음. S1에 권한 모델과 게이트(약간), A1에 분석 이벤트. IA는 바뀌지 않습니다. 행정 요건은 출시 뒤 결제를 켜기 전까지 따로 준비합니다.

## 4. 결정 (D53)

사용자가 제시된 (가)~(다) 밖의 안을 골랐습니다. **(라) 광고를 넣고 1개월 광고 제거권을 판매하며, 구독 결제는 MVP 이후에 구현합니다.**

* 광고 형식과 자리: 적응형 배너(adaptive banner)를 탭 루트 4곳(today·calendar·diary-list·my-saju) 하단에만 둡니다. 일기 작성·보기, 온보딩·미리보기, 시트에는 넣지 않습니다. 전면 광고(interstitial)와 네이티브 광고는 쓰지 않습니다.
* 광고 제거권: 1개월, 자동 갱신 없음. Apple은 비갱신 구독(non-renewing subscription), Google은 일회성 상품(one-time product)입니다. 비갱신 구독은 스토어가 복원해 주지 않으므로 server의 entitlement(만료일)로 복원합니다.
* 이 안이 판단 기준에 맞는 이유:
  * 기준 1: 핵심 경험은 무료입니다. 광고 자리를 탭 루트 하단 배너로 좁혀 재방문 지표와 "차분하다" 원칙을 덜 해칩니다.
  * 기준 2: 출시 첫날부터 실제 결제(광고 제거권)를 봅니다. 점신이 같은 모델(광고 + 광고 제거 월 ₩2,900)을 씁니다(§2.1).
  * 기준 3: 광고 제거는 기능 단위 접근 제한이라 D12와 맞고, D11·D23·D24를 바꾸지 않습니다.
* 대가: 출시 전에 사업자등록·통신판매업 신고가 필요하고, 첫 심사에 인앱결제 요건(복원, 가격·기간 고지, 약관 링크)이 더해집니다. 광고 동의(ATT·UMP) 흐름이 생깁니다.

### 가격 (D54)

잠정 가격은 **₩2,500**입니다(두 스토어 같은 값, 부가세 포함, 다른 나라는 스토어 자동 환산). 출시 전에는 실제 데이터가 없고, 비갱신 상품은 가격을 언제든 바꿀 수 있어 지금 잠정값을 정하고 출시 뒤 지표로 다시 봅니다.

| 근거 | 내용 | 출처 |
| --- | --- | --- |
| 가격 단위 | Apple 한국 스토어는 ₩20,000까지 100원 단위. Google은 직접 입력. 두 스토어에 같은 값 가능(추정, 콘솔에서 확인) | [Apple 뉴스룸](https://www.apple.com/kr/newsroom/2022/12/apple-unveils-changes-for-developers-in-south-korea/) |
| 시장 | 1개월 광고 제거는 ₩2,500~₩3,300(점신 ₩2,900, 위플 가계부 ₩2,500, 오늘의 그림일기 ₩3,300). 모두 자동 갱신이라 비갱신인 우리 상품과 성격이 다름 | App Store KR 각 앱 페이지 |
| 실수령 | ₩2,500 ÷ 1.1 × 0.85 ≈ ₩1,930(부가세를 뺀 뒤 수수료 15%, 추정) | [Apple 뉴스룸](https://www.apple.com/kr/newsroom/2022/12/apple-unveils-changes-for-developers-in-south-korea/) |

₩2,500을 고른 이유: 기준 2는 객단가가 아니라 "돈을 내는 사람이 있는가"를 보는 것이고, 비갱신 상품은 매달 직접 다시 사야 하므로 시장 범위의 아래쪽이 전환과 재구매 부담에 유리합니다.
