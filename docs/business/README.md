# 수익화 결정 체계

수익화 결정을 다루는 절차와 판단 기준입니다(D52). 설계 근거는 [M0 spec](../specs/2026-10-11-m0-monetization-design.md)에 있습니다. 아이디어는 [아이디어 함](../ideas.md)에 받고, 이 체계는 그중 수익 관점이 열린 것을 가져와 다룹니다.

## 파일

| 파일 | 내용 |
| --- | --- |
| `README.md` | 판단 기준, 사이클 절차, 여는 때, 작업 단위 분리 기준 (이 문서) |
| `cycles/YYYY-MM-DD-<주제>.md` | 사이클 하나에 문서 하나 |

* 고치는 쪽은 지휘 세션입니다. 다른 단위의 수익 관련 요청은 `to:root` Issue로 받습니다.
* 결정은 따로 번호를 두지 않고 [`docs/decisions.md`](../decisions.md)에 영역 "수익"의 D번호로 기록합니다. 사이클 문서에는 근거와 조사를 둡니다.

## 판단 기준

기준을 바꿀 때는 D번호로 기록합니다.

1. **사용자·재방문 지표가 먼저입니다.** 출시 후 3~6개월은 쓰는 사람을 모으고 다시 오는지 봅니다. 핵심 경험(오늘 풀이, 일기, 달력)은 결제로 막지 않습니다.
2. **작은 수익이라도 실제로 돈을 내는 사람이 있는지 검증합니다.** 1을 해치지 않는 범위에서 유료 후보의 수요를 확인합니다.
3. **이미 정한 결정을 지킵니다.** 정보 깊이는 유료 등급이 아니고(D11), 차등은 기능 단위 접근 제한이나 횟수 제한이며(D12), LLM 기능은 유료입니다(D23).

## 사이클 절차

사이클 문서는 아래 다섯 절을 이 순서로 채웁니다. 머리말의 `상태:` 줄에는 지금 채우는 단계(`질문`·`조사`·`선택지`·`결정`)를 적고, 다섯 절을 다 채우면 `반영 완료`로 바꿉니다.

1. **질문:** 답할 질문 하나, 그 답이 바꿀 수 있는 범위(IA·S1·A1·writing·design), 함께 다룰 아이디어 id. 아이디어 함에서 `수익`이 `유료 후보`·`미정`이고 상태가 `대기`인 것을 먼저 훑고, 묶은 것은 상태를 `검토 <이 사이클 문서 경로>`로 바꿉니다.
2. **조사:** 항목마다 출처(URL과 확인 날짜)를 붙입니다. 확인한 사실과 추정을 나누고, 추정에는 "추정"이라고 씁니다.
3. **선택지:** 2~3개. 각각 판단 기준 1·2·3에 비춘 평가와 범위 영향을 적습니다.
4. **결정:** 사용자가 고릅니다. 고른 선택지와 이유를 적고 D번호를 답니다.
5. **반영:** 고친 문서와 보낸 notice를 목록으로 남깁니다. 범위가 바뀌지 않았으면 "범위 변경 없음"과 근거를 적습니다. 다룬 아이디어의 상태를 `채택 Dn`·`보류`·`기각`으로 바꿉니다.

## 다음 사이클을 여는 때

* 사용자가 요청할 때
* 아이디어 함에 `수익`이 `유료 후보`·`미정`인 `대기` 아이디어가 3개 이상 쌓였을 때
* 출시 전후로 지표가 생겼을 때
* Phase 2 유료 기능(LLM, D23)에 착수할 때
* 다른 단위가 수익 관련 Issue를 올렸을 때

## 작업 단위로 나누는 기준

사이클 문서가 3개를 넘거나, 한 사이클이 지휘 세션의 다른 일(요청함 검토, 착수 안내)을 한 주 넘게 막으면, writing·design처럼 별도 작업 단위로 나눌지를 그때 정합니다.
