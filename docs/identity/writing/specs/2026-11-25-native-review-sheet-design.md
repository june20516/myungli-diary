# 원어민 검수 시트 설계 (#1283)

날짜: 2026-11-25. 근거: D140(앱 없이 writing이 내보낸 언어별 시트로 문장만 검수), E18(영어, 일본어 원어민 검수), I4(출시) 전.

## 1. 목표

* 감수자는 앱 없이 시트 한 장으로 en, ja 원고를 보고 고칠 곳을 적습니다.
* writing은 묶음(원고 파일)별로, 차수별로 시트를 내보냅니다.
* 돌아온 시트를 키로 원고에 반영하고, 상한과 검사기를 다시 돌립니다. 반영하지 않은 수정안에는 이유를 남깁니다.
* 범위 밖: 법적 문서 원문(원고 파일이 아님), ko 원고 검수, 원고 번역 자체.

## 2. 흐름

```
mlw review-export  ──>  review/<언어>/<이름>.xlsx (저장소)
                          │ 사용자가 Google Drive에 올림 → Google Sheets로 변환, 감수자에게 공유
                          │ 감수자가 수정안, 분류, 메모를 적음
                          │ 사용자가 "파일 > 다운로드 > xlsx"로 받음 → $MYUNGLI_LOCAL_DIR/writing/review/
mlw review-import <받은 시트>  ──>  content/<언어>/*.yaml 갱신 + 결과 시트(로컬) + check, gen-docs
```

* 형식은 xlsx입니다(`openpyxl` 의존성 추가). 감수는 Google Sheets에서 합니다. 안내 탭, 숨긴 칸과 탭, 목록 드롭다운이 변환 뒤에도 남습니다. Sheets API 직접 연동은 하지 않습니다(키 발급과 네트워크 코드에 견줘 얻는 것이 손작업 두 번뿐).
* 내보낸 빈 시트는 공개 원고뿐이라 저장소(`docs/identity/writing/review/`)에 둡니다. 돌아온 시트와 결과 시트는 감수자 이름이 파일 속성이나 댓글에 남을 수 있어 저장소 밖 로컬에만 둡니다(D98).

## 3. 묶음과 차수

묶음은 대상 언어 원고 파일 이름(확장자 뺌)입니다. 차수는 코드 상수 하나로 둡니다.

| 차수 | 묶음 |
| --- | --- |
| 1 | `store`, `ui`, `system`, `web` |
| 2 | `daily-fortune`, `daily-cards`, `daily-reasons`, `personal`, `calendar`, `chart` |
| 3 | `term`, `glossary`, `evidence`, `source` |

* `web`(#1329 랜딩)은 Issue 작성 뒤 생긴 공개 문장이라 1차에 넣습니다.
* 상수에 없는 원고 파일이 생기면 `review-export`가 오류를 냅니다. 묶음이 검수에서 빠지는 일을 막습니다.

## 4. 내보내기: `mlw review-export`

```
mlw review-export <content_dir> --lang en --tier 1
mlw review-export <content_dir> --lang ja --bundle store,ui
```

* `--tier`와 `--bundle` 중 하나만 받습니다. `--lang`은 `en`, `ja`입니다.
* 출력: `docs/identity/writing/review/<언어>/tier<n>.xlsx` 또는 `<묶음>-<묶음>.xlsx`. 다시 내보내면 덮어씁니다(이력은 git).
* `--out`으로 경로를 바꿀 수 있습니다(테스트용).

### 4.1 탭

1. **안내 탭**(첫 탭): `review/guide-<언어>.md`를 읽어 문단마다 한 셀에 넣습니다. 내용은 감수자 언어로 씁니다.
   * 톤: `guide/voice-tone.md`의 해당 언어 요약(친근하되 가볍지 않게, 단정하지 않음 등).
   * 고치면 안 되는 것: 자리표시자(`{name}`, `{count, plural, ...}`)와 용어 표기(`[[...|...]]`는 시트에 보이지 않고 `예시`에만 반영됨, 용어 탭의 값 이름은 3차에서 따로 봄).
   * 글자 상한: `자리 설명`의 상한을 넘으면 반영하지 못함.
   * 분류 값 네 가지의 뜻: 오역(뜻이 다름), 어색함(뜻은 맞지만 원어민이 쓰지 않는 말), 문법(문법, 철자, 구두점), 용어(같은 대상을 다른 말로 부름, 용어 표기 문제).
   * 금지 문자: 긴 대시, 범위 대시, 가운뎃점(D93).
   * 칸 설명과 작성 예 한 줄.
2. **묶음 탭**: 묶음마다 탭 하나, 탭 이름은 묶음 이름입니다.
3. **`_meta` 탭**(숨김): 언어, 내보낸 commit SHA, 내보낸 날짜, 도구 버전. 다시 읽을 때 언어를 여기서 읽습니다.

### 4.2 묶음 탭 칸

대상 언어 원고 한 줄(ICU 전개 전)이 한 행입니다. 칸 머리는 `감수자 언어 (한국어)` 형식입니다(예: `Suggestion (수정안)`).

| 칸 | 내용 | 감수자 편집 |
| --- | --- | --- |
| `id` (숨김) | `<slot>\|<key>\|<type>\|<variant>`. 유형이 없으면 `type` 자리는 비움 | 아니오 |
| 키 | `<key>` (유형, 변주가 있으면 `<key> / <type> #<variant>`) | 아니오 |
| 묶음 | 묶음 이름 | 아니오 |
| 자리 설명 | 슬롯 `where`, 줄 바꾸고 상한(`최대 N자`, 바이트 단위면 `최대 N바이트`, `max_lines`면 `N줄`, 상한 없음, 미정). 키별 상한이 있으면 그것 | 아니오 |
| 한국어 원문 | ko 원고에서 같은 `(slot, key, type, variant)` 줄의 `text`. ko 파일 구성이 달라(`daily.yaml`) 파일이 아니라 이 네 값으로 찾습니다. 없으면 빈 칸 | 아니오 |
| 현재 번역 | 대상 언어 `text` 원문 그대로(자리표시자, 용어 토큰 포함) | 아니오 |
| 예시 | 아래 4.3 규칙으로 채운 모양. 복수형이면 형태마다 한 줄 | 아니오 |
| 수정안 | 비움 | 예 |
| 분류 | 비움. 드롭다운(네 값, 감수자 언어 표기) | 예 |
| 메모 | 비움 | 예 |
| writing 판정 | 비움. 감수 뒤 writing이 반영하지 않을 줄에 이유를 적는 칸 | writing |

* 편집하지 않는 칸은 회색 배경, 첫 행 고정, 자동 줄바꿈, 칸 너비 고정입니다.
* 시트 보호는 걸지 않습니다(Sheets 변환에서 사라질 수 있음). 잘못 고친 줄은 다시 읽을 때 걸러집니다.

### 4.3 예시 값

`placeholders.substitute`로 자리표시자를 채우고 `strip_token_marks`로 용어 토큰 표시를 뺍니다.

* `glossary`: 그 범주의 대상 언어 값 이름 중 **첫째**(원고 순서). 가장 긴 값이 아니라 보통 값입니다.
* `list`: 같은 범주 값 이름 둘을 `, `로 잇습니다.
* `number`: `3`. 복수형(ICU)은 `icu.expand_entry`로 형태를 모두 보입니다.
* `text`: 키별 표본이 없으므로 `‹<자리표시자 이름>›`(예: `‹date›`)로 둡니다.
* `name`(호칭): 언어별 표본 상수(en `Alex`, ja `ゆき`, 각 언어 `onboardCallInputHint`의 예와 같음).
* 해석할 수 없는 자리표시자는 그대로 둡니다(검사기가 따로 막음).

## 5. 다시 읽기: `mlw review-import`

```
mlw review-import <content_dir> <받은 시트.xlsx> [--dry-run]
```

1. `_meta`에서 언어를 읽고, 묶음 탭의 행을 `id`로 원고 줄에 맞춥니다. `수정안`이 빈 행은 건너뜁니다.
2. 행마다 판정합니다. 하나라도 걸리면 그 행은 **반영 안 함**이고 이유를 남깁니다.
   * `writing 판정`이 적혀 있음 → 그 내용이 이유.
   * `id`에 맞는 원고 줄이 없음 → "원고에 없는 줄".
   * 시트의 `현재 번역`이 지금 원고 `text`와 다름 → "내보낸 뒤 원고가 바뀜, 다시 확인".
   * 수정안의 자리표시자 이름과 용어 토큰(id)이 현재 번역과 다름(개수 포함). 감수자는 토큰 표시 없이 쓸 수 있으므로, 현재 번역에 토큰이 있으면 같은 표기의 값 이름 텍스트를 찾아 토큰으로 되감습니다. 되감지 못하면 "용어 표기가 바뀜, writing이 직접 반영".
   * 수정안이 현재 번역과 같음 → "변경 없음".
3. 통과한 행을 임시 사본의 원고에 적용하고 `mlw check`와 같은 검사(상한, slop, 스타일, D93 등)를 돌립니다. 바뀐 줄을 가리키는 error가 있으면 그 행을 되돌리고 finding 메시지를 이유로 남깁니다. 되돌린 뒤 더 나오지 않을 때까지 반복합니다.
4. 남은 행을 실제 원고 파일에 씁니다. 원고 줄의 `text: "..."` 값만 바꾸고 주석, 순서, 다른 필드는 그대로 둡니다. 바꾼 파일은 다시 읽어 `text`가 수정안과 같은지 확인합니다.
5. 결과 시트를 받은 시트 옆에 `<이름>-result.xlsx`로 씁니다. 모든 행 끝에 `반영 결과` 칸(`반영함` 또는 `반영 안 함: <이유>`)을 더합니다. 감수자 `메모`는 건드리지 않습니다.
6. 끝에 원고 전체 `check`와 `gen-docs`(ARB, 웹 JSON 등 생성물)를 돌리고 요약(반영 수, 반영 안 한 수와 이유별 수)을 출력합니다.

* `--dry-run`은 3까지만 하고 원고를 쓰지 않습니다(결과 시트는 씀).
* 받은 시트가 저장소 안 경로면 경고합니다(감수자 정보가 섞일 수 있음).
* 분류가 `용어`인 행은 반영 여부와 함께 요약에 따로 셉니다. 같은 용어가 여러 곳에 있을 수 있어 writing이 glossary와 맞춰 보는 신호입니다.

## 6. 코드 구성

* `review/sheet.py`: 행 모델(`ReviewRow`), 차수 상수, xlsx 쓰기와 읽기(openpyxl). 원고 모델에 의존하지 않습니다.
* `review/export.py`: 원고, 슬롯, 용어집 → `ReviewRow` 목록, 예시 렌더.
* `review/apply.py`: 행 판정, 원고 줄 텍스트 교체(YAML 큰따옴표 문자열 이스케이프), 검사 반복.
* `cli.py`: `review-export`, `review-import` 하위 명령.
* 안내 원문: `docs/identity/writing/review/guide-en.md`, `guide-ja.md`.

## 7. 검사

* 내보내기 → 수정안 채움 → 다시 읽기 왕복(tmp 사본 원고)으로 `text`가 바뀌고 나머지 줄과 주석이 그대로인지.
* 자리표시자를 지운 수정안, 토큰 표시 없이 쓴 수정안(되감기 성공, 실패), 원고가 바뀐 줄, `writing 판정`이 적힌 줄, 상한을 넘는 수정안, 가운뎃점이 든 수정안의 판정.
* 큰따옴표, 역슬래시, 줄바꿈이 든 수정안의 YAML 쓰기와 다시 읽기.
* 예시 렌더(glossary, list, number와 복수형, name, text).
* 차수 상수가 실제 원고 파일 목록과 정확히 같은지(빠짐, 남음 없음).
* 저장소 원고로 1차 en, ja 내보내기가 오류 없이 되는지.

## 8. 기록과 계약

* 검사기 버전을 0.16.0으로 올리고 계약 표 검사기 행과 CHANGELOG에 적습니다. 원고 형식은 바뀌지 않습니다.

* 1차 en, ja 시트를 저장소에 넣고 #1283에 위치를 남깁니다.
