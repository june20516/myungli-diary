# IA 슬롯 정렬과 ui 슬롯 Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** writing 슬롯 명세가 IA 124자리를 모두 담게 합니다. 이를 위해 검사기를 v0.2.0으로 올리고, ui 91자리의 명세·3개 언어 원고·ARB를 냅니다.

**Architecture:**
- 검사기(`mlw`)에 IA 대조(`ia.py`), 호칭·ui 표기 검사(`markup.py`), 용어 토큰 검사(`terms.py`), ARB 생성(`arb_export.py`)을 새 모듈로 더합니다.
- 슬롯 명세 YAML에 `ia`·`components`·`select`·`vocative`를 채우고, ui 슬롯 파일 7개와 ui 원고를 씁니다.
- 바깥 영향(server 렌더, app ARB, core 자료, design 상한)은 Issue로 알립니다.

**Tech Stack:** Python 3.12 + uv, pytest, ruff, mypy, PyYAML, regex (기존 `docs/identity/writing/tools`)

**Spec:** `docs/identity/writing/specs/2026-10-13-ia-slots-design.md`

## Global Constraints

- 고치는 곳은 `docs/identity/writing/`과 GitHub Issues뿐입니다. `docs/ia/screens.json`은 읽기만 합니다.
- 명령은 `docs/identity/writing/tools`에서 실행합니다. CI 단계는 다음과 같습니다.
  - `uv run ruff check .`
  - `uv run mypy src`
  - `uv run pytest -q`
  - `uv run mlw gen-docs --check`
  - `uv run mlw check ../content --partial`
- 문서·주석·원고 설명은 한국어 해요체가 아니라 기존 파일과 같은 합니다체입니다. 원고 문장은 가이드(해요체, W6)를 따릅니다.
- ui 키 이름: `lowerCamelCase(IA id)`, 그 뒤에 숫자 접미사(`1`, `2`) 또는 대문자로 시작하는 상태 이름이 붙을 수 있습니다. 하이픈과 점은 단어 경계입니다.
- 호칭 덩어리: ko `{name}님, `, ja `{name}さん、`, en `{name}, `. 문장 맨 앞에서 `vocative: true` 슬롯에만 씁니다.
- 용어 범주: `element`, `stem`, `branch`, `ten_god`, `ten_god_group`, `shinsal`, `day_kind`, `relation`, `role`, `luck`, `tag`. 용어 id는 모두 77개입니다.
- 글자 수 상한은 `docs/identity/design/lengths.md` 확정값을 그대로 씁니다.
- 기존 슬롯 id·메시지 키는 바꾸지 않습니다. 예외는 `settings.calculation_basis`를 지우는 것 하나입니다.
- 커밋 메시지 끝 두 줄:
  - `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`
  - `Claude-Session: https://claude.ai/code/session_01HHUvecxNw8Fix2cZo5D4RH`

## Review Focus

1. 점이 여럿이고 하이픈이 든 IA id(`day-sheet.diary.write-cta`)는 `daySheetDiaryWriteCta`가 되어야 합니다. 상태 접미사가 붙은 `daySheetDiaryWriteCtaSaved`도 허용하고, 소문자로 이어 붙인 `daySheetDiaryWriteCtasaved`는 거부해야 합니다.
2. 호칭 뒤 쉼표나 공백을 빠뜨린 원고(`{name}님 오늘은`)와 문장 중간의 `{name}`은 `name.position` error여야 합니다.
3. en 호칭을 지운 뒤 다음 글자가 `[[`나 `{`로 시작하면 대문자 처리를 건너뛰어야 합니다. 렌더 후의 대문자화는 server 몫이고, 검사기는 지운 텍스트로만 검사합니다.
4. `[[{element:color}]]`처럼 용어 범주가 아닌 범주를 감싼 토큰과 `[[신|stem.unknown]]`처럼 없는 id는 `token.term` error여야 합니다.
5. en·ja ui 원고가 일부 비어 있으면 그 언어 ARB에서 그 키를 빼야 합니다(빈 문자열 금지). `@키` 메타데이터는 ko 파일에만 둡니다.
