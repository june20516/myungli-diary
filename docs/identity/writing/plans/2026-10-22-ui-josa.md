# ui 원고의 조사 렌더 Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** ko ui 원고의 매개변수 뒤 조사 표기를 ARB 생성 때 ICU `select`로 펼치고, 검사기가 그 표기와 펼친 ARB를 검사하게 합니다.

**Architecture:** 펼치기는 새 모듈 `mlw/josa_select.py` 하나가 맡고, `arb_export`(생성)와 `icu`(check-arb의 가지 펼치기)가 그것을 씁니다. ui 원고 검사는 `markup.py`에 규칙 셋을 더해 `cli.markup_findings`에서 부릅니다. 조사 값은 모두 `rules/josa.yaml`의 `pairs`에서 옵니다.

**Tech Stack:** Python 3.12, `regex`, pytest, ruff, mypy (`docs/identity/writing/tools`, `uv run`)

**Spec:** `docs/identity/writing/specs/2026-10-22-ui-josa-design.md`

## Global Constraints

* 명령은 `docs/identity/writing/tools`에서 `uv run pytest -q …`, 원고 검사는 저장소 루트에서 `uv run --project docs/identity/writing/tools mlw …`.
* 가지 이름은 정확히 `final`·`rieul`·`none`·`other`이고, 이 순서로 씁니다.
* 생성 매개변수 이름은 `<원래 이름>Josa`, ARB 자리표시자 타입은 `String`, description은 `app이 josaClass(<원래 이름>)로 채움`.
* 조사 표기 허용은 ko ui 원고만입니다. en·ja ui 원고의 조사 표기, ui의 `{name}`·용어 토큰은 지금처럼 `ui.markup` error.
* 이 plan은 원고(`content/*/ui.yaml`)에 조사 표기를 쓰지 않습니다. 끝났을 때 `mlw gen-docs --check`가 바뀐 생성물 없이 통과해야 합니다.
* 코드 주석·docstring·메시지는 기존 모듈처럼 한국어 경어체입니다.
* 검사기 버전은 `tools/pyproject.toml`의 `version = "0.8.0"`.

## Review Focus

1. 한 문장에 같은 매개변수가 서로 다른 조사로 두 번 나옴(`{p}(이)가 … {p}(을)를`) → `pJosa` 자리표시자는 하나, `select`는 두 개.
2. plural 가지 안의 조사(`{count, plural, other{{count}(이)에요}}`) → 펼친 ARB가 `icu.plural`을 통과하고, check-arb가 plural × select 가지를 모두 문장으로 검사.
3. `ui.josa_literal` 오검출: `{date}이후`, `{count}개`, `{end}에`, `{tag} 태그`는 통과, `{provider}로 로그인`·`{title}이 내일`은 error.
4. 조사 표기가 매개변수 없이 맨 글자 뒤에 옴(`오늘(은)는`)이나 `none` 종류 매개변수 뒤 → `ui.josa_position` error.
5. 조사 표기가 없는 메시지의 ARB 출력이 바뀌지 않음(기존 키 시그니처 불변) → 저장소 생성물 `gen-docs --check` 통과.
