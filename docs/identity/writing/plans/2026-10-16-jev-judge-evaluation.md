# jev 판정 대체 가능성 과제 계획

* 날짜: 2026-10-16 (계획). **2026-10-20 실행: 대체하지 않음**(`artifacts/2026-10-20-jev-evaluation.md`, W32). 기준 ②는 빼고 ①③으로 판단했고, 정답 표본은 §3-1 대신 ko 기록 층별 30문항입니다
* 근거: W1 spec `specs/2026-10-16-w1-content-design.md` §6.2, 결정 W1·W27, TypeSafe 문서(https://docs.typesafe.ai/, 2026-10-16 확인)
* 입력: W1-1 첫 라운드의 shadow 판정 기록 `artifacts/judge-shadow/`(문장 단위 `claude -p` 표시와 jev `noul` 확률)

## 1. 묻는 것

`mlw judge`의 로컬 1차 거르기를 `claude -p`에서 jev로 바꾸거나, 두 엔진을 나눠 쓸 수 있는가? 판단 기준은 비용이 아니라 **판정이 같은 품질인가**입니다. jev는 입력 토큰 단가가 낮고 출력이 무료이며, `claude -p`는 호출당 고정분이 약 34k 토큰이기 때문입니다.

## 2. 준비된 것 (W1-1에서 만듦)
* `mlw judge --shadow jev`: 본 판정과 같은 문장을 jev에 보내 확률을 기록합니다. 키는 환경 변수 `TYPESAFE_API_KEY`로만 받습니다(키 파일은 저장소 밖).
* `artifacts/judge-shadow/`: 첫 라운드의 두 엔진 판정 쌍입니다.

## 3. 검사 순서
1. **정답 표본 만들기:**
   * 표본은 slop 규칙 예시(llm 규칙 5개, 걸리는 예 7 + 통과 예 5)와 슬롯 명세의 좋은 예·나쁜 예입니다.
   * 여기에 첫 라운드에서 사용자가 판단한 문장(라운드 기록)을 정답으로 더합니다.
   * 언어별로 따로 셉니다.
2. **균질성 검사(같은 문장, 두 엔진):**
   * 규칙별·언어별 일치율과 Cohen's kappa를 냅니다.
   * jev 임계값을 0.3·0.5·0.7로 바꿔 가며 일치율이 어떻게 변하는지 봅니다.
   * 의견이 갈린 문장 목록을 만들고 jev 확률·confidence와 `claude -p` 이유를 나란히 놓습니다.
3. **정답 표본 정확도:** 두 엔진의 정밀도와 재현율을 언어별로 냅니다. 1차 거르기라 놓치는 쪽(재현율)을 더 무겁게 봅니다.
4. **jev 한도:** 첫 라운드에서 언제 한도에 걸렸는지, 몇 요청을 처리했는지 기록에서 봅니다.

## 4. 판단 기준 (실행 전에 사용자와 확정)
초안입니다. 아래 셋을 모두 넘으면 대체를 고려합니다.
* ko: 정답 표본 재현율이 `claude -p` 이상입니다.
* 규칙별 kappa가 0.6 이상입니다.
* 의견이 갈린 문장을 사람이 봤을 때 jev 쪽이 틀린 비율이 절반 이하입니다.

ja·en은 따로 판단합니다. 문서상 CJK 정확도가 영어보다 낮으므로, ko·ja 중 하나만 넘으면 언어별로 엔진을 나눠 쓰는 안도 봅니다.
