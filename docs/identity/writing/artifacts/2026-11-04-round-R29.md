# 라운드 R29: 문의 화면 원고 (W54)

* 날짜: 2026-11-04 · 진행: writing 세션(터미널) · 판정: 사용자
* 근거: D102(앱 안 문의 화면, D89 ① 개정), #752(IA `contact` 슬롯), #745(D89 문의하기 원고)
* `mlw judge`(ko): `contactAttachedNotice`의 "활용됩니다"를 문어투 피동으로 표시(`slop.P9` warn). 사용자가 직접 "씁니다"를 "활용됩니다"로 고친 말이라 그대로 둡니다. 나머지는 의심 없음.
* 대조군: R29-1의 2, R29-2의 1과 다시 낸 2, R29-3의 3, R29-5의 2, R29-6의 3. 한 번도 골리지 않았습니다.
* 같은 문항 다시 내기: R29-4를 순서를 바꿔 다시 냈고 같은 답이었습니다.

## 문항과 선택지 (낸 순서 그대로)
**R29-1 화면 위 안내** `contactIntroBody`
1. 궁금한 점이나 불편한 점을 적어 주세요. 답은 적어 주신 메일로 보내 드려요.
2. 어떤 이야기든 소중히 듣고 있어요! 편하게 마음을 들려주세요. (대조군)
3. 문의 내용과 답장 받을 메일 주소를 적어 주세요. 답은 메일로 와요.
4. 다 별로

**R29-2 함께 보내는 정보 고지** `contactAttachedNotice`
1. 더 나은 도움을 위해 몇 가지 정보를 안전하게 함께 전달해요! (대조군)
2. 계정 id, 앱 버전, 기기 정보(OS, 기종)를 함께 보내요. 문의를 확인하는 데만 써요.
3. 문의를 바로 확인할 수 있게 계정 id, 앱 버전, 기기 정보(OS, 기종)도 자동으로 함께 보내요. 문의 처리에만 써요.
4. 다 별로

사용자: "안내는 다로 끝내기로 하지않았나?" 고정 규칙은 없지만(W43) 수집 고지는 공적 사실이라 합니다체가 자연스럽다는 기준(W40, W43)에 맞춰 다시 냈습니다.

**R29-2 다시 내기(합니다체)**
1. 문의와 함께 계정 id, 앱 버전, 기기 정보(OS, 기종)가 자동으로 전송됩니다. 이 정보는 문의 처리에만 씁니다.
2. 고객님의 소중한 정보는 안전하게 보호되며, 더 나은 서비스를 위해서만 활용됩니다. (대조군)
3. 계정 id, 앱 버전, 기기 정보(OS, 기종)를 함께 보냅니다. 문의 처리에만 씁니다.
4. 다 별로

사용자: "문의 처리에만 씁니다 => 문의 처리에만 활용됩니다." 어느 앞 문장에 붙일지 물었고 3을 골랐습니다.

**R29-3 보낸 뒤 toast** `contactSentToast`
1. 문의를 보냈어요. 답은 메일로 보내 드릴게요.
2. 문의를 보냈어요.
3. 소중한 문의 감사해요! 최대한 빨리 답해 드릴게요. (대조군)
4. 다 별로

**R29-4 구매 내역 안내** `purchaseHistoryMissingNotice` (R28-3 다시 묻기: 안내를 누르면 문의 화면으로 바로 감)
1. 결제한 상품이 보이지 않으면 문의해 주세요.
2. 결제한 상품이 보이지 않으면 설정의 문의하기로 알려 주세요. (R28-3)
3. 결제한 상품이 보이지 않으면 문의하기로 알려 주세요.
4. 다 별로

**R29-4 다시 내기(순서 바꿈)**: 2, 3, 1, 4 순서

**R29-5 문의 내용 칸** `contactMessageFieldLabel` / `Hint`
1. 문의 내용 / 어떤 일이 있었는지 적어 주세요
2. 문의 내용 / 무엇이든 편하게 남겨 주세요 :) (대조군)
3. 문의 내용 / 언제, 어느 화면에서 있었던 일인지 함께 적어 주세요
4. 다 별로

**R29-6 답장 받을 메일 칸** `contactEmailFieldLabel` / `Hint`
1. 답장 받을 메일 / name@example.com
2. 메일 주소 / 답은 이 주소로 보내 드려요
3. 답장 받을 메일 / 정확히 적어 주셔야 답장이 제대로 갈 수 있어요! (대조군)
4. 다 별로

## 묻지 않고 반영한 것
* 제목 `contactBarTitle` 문의하기(설정 줄 이름과 같음), 버튼 `contactSendCta` 보내기(저장 버튼과 같은 동작 이름).
* 주소 안내 `contactAddressNote`: "보내기가 안 되면 이 주소로 메일을 보내 주세요." 다음 줄에 `{email}`(app이 E14 값으로 채움). 주소 뒤에 조사를 붙이지 않으려고 줄을 나눴고, R28-2에서 고른 "아래 주소로 메일을 보내 주세요"와 같은 말입니다.
* IA 밖 `ui.contact.error`: 보내기 실패 `contactSendFailed` "문의를 보내지 못했어요. 잠시 뒤 다시 보내 주세요."(로그인 오류와 같은 틀), 주소 형식 `contactEmailInvalid` "메일 주소를 다시 확인해 주세요."

## 굳힌 규칙
* W54: 수집 고지(보내는 정보와 쓰임)는 합니다체로 씁니다(W43의 공적 사실 기준). 누르면 바로 가는 안내는 거치지 않는 경로("설정의")를 말하지 않습니다.
