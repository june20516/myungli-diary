* 근거: app 요청 #468(D82, REST 계약 draft.14 #463의 problem code 6개)
* `mlw judge`: 돌리지 않았습니다. 짧은 오류 문구입니다.
* 대조군: R14-2 선택지 2 "로그인 여정에 작은 엇갈림이 생겼어요. 잠시 숨을 고르고 다시 시도해 주세요."(`slop.P1` 과한 추상화). 고르지 않았습니다.
* 커뮤니티 출처: 이번 문항은 오류 문구라 넣지 않았습니다.

## R14-0. 용어 "수단"
첫 후보를 보고 사용자가 "수단"만 따로 쓰는 것을 버렸습니다. 따로 쓸 자리에는 "인증 수단"을 씁니다(한글 맞춤법 제50항, 전문 용어는 띄어 쓰는 것이 원칙). 화면 이름 "로그인 수단"은 그대로 둡니다. 기존 원고 세 곳(`loginMethodsIntroBody`·`loginMethodsLastNotice`·`loginMethodsUnlinkConfirmBody`)도 고쳤습니다(W39).

## R14-1. 연결이 없는 인증 수단 떼기 (`auth.identity_not_found`)
선택지: 이 계정에 연결되어 있지 않은 인증 수단이에요. / 이미 연결이 끊겨 있어요. / **연결된 인증 수단을 찾지 못했어요. 화면을 다시 열어 주세요.**(선택) / 다 별로

## R14-2. 같은 종류에 다른 사용자 연결이 이미 있음 (`auth.provider_taken`)
선택지: **같은 인증 수단으로 연결한 다른 계정이 이미 있어요.**(선택) / 로그인 여정에 작은 엇갈림이 생겼어요(대조군) / 이 인증 수단으로는 이미 다른 계정을 연결해 두었어요. 먼저 그 연결을 끊어 주세요. / 다 별로

## R14-3. 다른 계정에 있는 인증 수단 (`auth.identity_in_use`, 대비 문구)
선택지: 이미 다른 계정에서 쓰는 인증 수단이에요. / 다른 계정에 연결된 인증 수단이에요. 다시 시도하면 두 계정을 합칠 수 있어요. / 다른 계정에 연결된 인증 수단이에요. 다시 시도해 주세요. / 다 별로
선택: 2·3의 앞 문장만, **다른 계정에 연결된 인증 수단이에요.**

## R14-4. 삭제 대기 계정에 있는 인증 수단 (`auth.identity_pending_deletion`)
선택지: 삭제 대기 중인 계정에 연결되어 있어요. 먼저 그 계정을 복구해 주세요. / 지우기로 한 계정의 인증 수단이에요. 그걸로 로그인해 되살린 뒤 다시 시도해 주세요. / 지우기로 한 계정의 인증 수단이에요. 그 인증 수단으로 로그인하면 계정이 되살아나요. / 다 별로
선택: 1의 앞 문장만, **삭제 대기 중인 계정에 연결되어 있어요.** 되살리는 방법은 알리지 않습니다. 계정 삭제 화면은 "되돌릴 수 없어요"라고 말하는데 server는 30일 안에 로그인하면 되살리므로, 그 어긋남은 따로 다룹니다.

## R14-5. 마지막 인증 수단 떼기 (`auth.last_identity`)
선택지: 마지막 인증 수단은 끊을 수 없어요. / 연결을 끊지 못했어요. 인증 수단이 하나는 남아 있어야 해요. / **인증 수단이 하나는 남아 있어야 해요.**(선택, `loginMethodsLastNotice`와 같음) / 다 별로

## R14-6. 합치기 토큰 무효 (`merge.token_invalid`)
선택지: 계정 합치기를 이어 가지 못했어요. 다시 로그인해 주세요. / 합치기 시간이 지났어요. 다시 로그인해 주세요. / **기존 `accountMergeError` 그대로**(선택) / 다 별로
처음에는 3을 골라 `accountMergeError`에 이었습니다(PR #470). 재출제 판에서 이 선택지의 우려를 빠뜨렸기 때문에 다시 물었습니다. 우려는 두 가지입니다. 응답을 잃고 다시 시도한 경우에는 이미 합쳐졌을 수 있는데 문구가 "두 계정 모두 그대로 있어요"라고 말합니다. 또 "다시 시도해 주세요"라고 하지만 app은 로그인 화면으로 보냅니다.
재선택: **새 키 `errorMergeTokenInvalid` "계정 합치기를 이어 가지 못했어요. 다시 로그인해 주세요."** 합쳐진 경우와 안 합쳐진 경우 모두 사실에 맞고, app 동작(로그인 화면)과도 맞습니다.

## 반영
* `ui.error.code`에 `errorAuthIdentityNotFound`·`errorAuthProviderTaken`·`errorAuthIdentityInUse`·`errorAuthIdentityPendingDeletion`·`errorAuthLastIdentity`·`errorMergeTokenInvalid`(추가만). en·ja는 같은 뜻의 초안입니다(D70). ja `errorAuthIdentityNotFound`는 상한 34자에 맞춰 "連携している"를 뺐습니다.
* 기존 키 세 개의 ko 문구가 "인증 수단"으로 바뀝니다(키 이름 그대로).
