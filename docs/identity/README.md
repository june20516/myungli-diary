# 명리일기 정체성 기준

## 이 문서의 위상
* 명리일기의 컨셉, 목소리, 시각 방향 가운데 **지금 유효한 기준**을 모았습니다. 정체성에 관해서는 이 문서가 `docs/background/`의 00·03·06 원문을 대체합니다(D38). 원문은 받은 그대로 둡니다.
* 고치는 쪽은 지휘 세션입니다. 각 항목이 왜 이렇게 정해졌는지는 [브랜드 기반 spec](../specs/2026-10-10-brand-foundation-design.md)에 있습니다.
* writing·design 작업 단위는 이 문서를 "브랜드 기반" 계약으로 사용합니다. 이 문서와 부딪히는 결정은 구현을 멈추고 요청함으로 올립니다.

## 컨셉과 포지셔닝

**컨셉 문장 (팀 내부용)**
> 오늘 일진을 내 사주에 맞춰 풀어주는 일기 앱

* 사용자에게 보이는 태그라인과 스토어 문구는 writing 작업 단위가 정합니다.
* 아침 알림·밤 일기처럼 사용 순서로 경험을 좁히는 표현은 쓰지 않습니다.

**포지셔닝:** 강점은 사주 일반이 아니라 **내 사주로 조합한 개인화**입니다.
* 사주 앱과 비교하면: 데일리·일간·주간·월간 운세는 띠나 일간 단위라 같은 날 같은 결과를 받는 사람이 많습니다. 명리일기는 일진 × 원국(D13)으로 사람마다 다른 오늘을 줍니다.
* 일기 앱과 비교하면: 일기 앱은 매일 같은 빈 페이지를 냅니다. 명리일기에서는 날마다 다른 오늘(D19 날의 성격, D22 가이드 질문)이 그날 일기의 출발점이 됩니다.

## 성격

존재 비유: **내 기록을 같이 보는 일기장.** 차분하고, 기록하는 사람이 중심에 있습니다.

| 이렇다 | 이렇지 않다 |
| --- | --- |
| **차분하다:** 강조는 배지·색이 맡고 문장은 담담합니다 | 들떠 있다: 느낌표, 이모지, "완전 좋은 날" |
| **구체적이다:** 무엇이, 언제, 어떻게인지 말합니다 | 목적 없이 추상적이다: 기능 안내에서 "흐름이 보여요" |
| **곁에 있다:** 위로·공감이 목적인 자리에서는 운세체의 다정함도 씁니다 | 아무 데서나 다정하다: 정보 슬롯에서 "마음의 온도" |
| **아는 만큼 보여준다:** 문장에는 용어만 두고, 표시로 알아보게 하고, 풀이는 한 단계 아래에 둡니다 | 가르치려 든다: 괄호 풀이, 처음부터 용어 설명 |
| **이름을 불러준다:** 한 화면에 한 번 호칭으로 부릅니다 | 친한 척한다: 문장마다 이름을 부름 |

**문장이 하는 일:** 행동 조언, 상태 설명, 감정 돌봄 세 가지입니다(§공용 용어의 문장 유형). 기록을 권하며 앱이 해줄 일을 약속하는 문장과 메모식 요약은 쓰지 않습니다.

## 원칙

0. **slop은 표현 자체가 아니라 맥락과 빈도에서 생깁니다.**
   * 추상적이거나 운세체인 표현도, 슬롯의 목적이 위로·공감·감정이고 그런 상호작용 맥락이 있으면 씁니다.
   * slop이 되는 경우: ① 목적·맥락이 없는 자리에서 쓸 때 ② 한 화면·하루·한 주 안에서 남발할 때.
   * 그래서 슬롯마다 목적별 허용 표현 범위를 정하고, 검사기는 금지어 사전이 아니라 슬롯 목적과 빈도·밀도 상한으로 판단합니다.
1. **낮은 주의력으로도 알아볼 수 있어야 합니다.** 읽지 않고 훑어봐도 날의 성격과 용어 여부를 알 수 있게, 글보다 UI 표시(꾸밈·색·배지)를 먼저 씁니다.
2. **강조는 UI가, 문장은 담백하게.** 날의 성격과 강도는 배지·색으로 전합니다. 문장을 느낌표·이모지로 들뜨게 만들지 않습니다.
3. **영어로 생각하고 한국어로 옮긴 문장을 쓰지 않습니다.** 아래 slop 패턴 2~7이 대표적인 형태입니다.

## 공용 용어와 부품

* **깊이 (D37):** 정보를 펼치는 축입니다.
  | 단계 | 담는 내용 | 화면 |
  | --- | --- | --- |
  | `surface` 표면 | 카드 문장. 명리 용어는 표시만 합니다 | 카드 |
  | `explain` 풀이 | 용어 뜻, 오늘 그런 이유 | 하프 시트 |
  | `evidence` 근거 | 원국표, 판정 근거, 원전 | 풀 시트 |
  * 사용자가 어느 단계까지 먼저 펼쳐 볼지는 **기본 깊이** 설정입니다. 사용자에게 보이는 이름은 writing이 정합니다.
  * 옛 문서의 Easy는 `surface`, Pro는 `evidence`로 대체합니다.
* **호칭 (D36):** 앱이 사용자를 부르는 말입니다. 온보딩에서 필수로 받고, 실명이 아니어도 됩니다.
  * 한 화면에 한 번(첫 문장, 좋은 날·위로 같은 순간)만 부르고 나머지 문장은 호칭을 생략합니다.
  * 일본어는 〇〇さん, 영어는 경칭 없이 이름만 쓰되 더 드물게 부릅니다.
  * "님"·"さん" 접미사, 조사 처리(은/는·이/가 등), 입력 검증은 writing이 정합니다.
* **용어 토큰:** 문장 안의 명리 용어를 꾸밈·색으로 표시하고, 탭하면 `explain` 단계를 엽니다.
  * writing: 어떤 단어를 용어로 표시할지 정합니다.
  * design: 표시 방식과 열리는 화면을 정합니다.
* **문장 유형 (D40):** 조언 `advice` · 상태 `state` · 돌봄 `care`. 콘텐츠 문장을 만드는 축입니다.
  * MVP는 유형을 순환해 보여주고 사용자 반응(좋아요)을 수집합니다. 반응에 맞춰 유형을 고르는 일은 Phase 2입니다.
  * 반응은 같은 날 종류(D19) 안에서 유형끼리 비교합니다.

## 시각 방향

* **톤:** 파스텔 그라데이션 바탕(세이지 그린 → 코랄 핑크 계열)에 둥근 고딕 본문(고운돋움, SIL OFL)을 씁니다.
  * 그라데이션은 AI 화면에서 흔한 인상이라는 점을 알고 고른 **조건부 선택**입니다. 써보고 불쾌감이 들면 리뉴얼합니다. design은 그라데이션을 토큰 하나로 묶어 교체하기 쉽게 둡니다.
* **정보 가시성:** 정보는 칩과 표시로 정돈합니다. 예쁨과 가독성이 부딪히면 가독성을 우선합니다.
* **데일리 카드 레이아웃:** 흰 패널 없이 그라데이션 바탕 위에 날짜 → 날의 성격 배지 → 문장(용어 토큰 포함) → 아래쪽 반투명 칩 한 줄(행운 색 견본·방향·숫자) 순서로 놓습니다.
* **시안 색 값 (참고용, 확정은 design V1):**
  | 쓰임 | 값 |
  | --- | --- |
  | 바탕 그라데이션 | `#eef4ef` → `#fbefee` (160°) |
  | 좋은 날 배지 | 바탕 `#f4b6ae`, 글자 흰색 |
  | 용어 토큰 | 바탕 `#e3efe6`, 글자 `#4f7f5e`, 굵게 |
  | 칩 | 흰색 70% 불투명 |

## slop 패턴

writing 작업 단위는 이 목록에서 출발해 넓힙니다.

1. **목적 없는 자리의 과한 추상화.** 기능·정보 슬롯에서 무엇이 어디서 어떻게인지 말하지 않는 문장. 예: "흐름이 보여요", "나를 알게 돼요". 실제로 일어나는 결과를 씁니다. 위로·공감 슬롯은 원칙 0에 따라 예외입니다.
2. **정의형 소개.** "X는 ~한 Y입니다"(영어 "X is a Y that…"의 틀). 무엇을 해주는지부터 말합니다.
3. **사물 주어 의인화.** "사주를 아는 일기장"처럼 사물이 알고 느끼게 하는 영어식 관계절.
4. **시점 혼재와 기획 용어 노출.** 한 문장에서 "내"와 "사용자"가 섞이거나, "사용자"·"콘텐츠" 같은 기획 용어가 화면 문장에 나옴.
5. **번역 슬로건.** "주인공은 언제나 당신" 같은 틀.
6. **자기 성격 형용.** "차분하게 알려드려요"처럼 톤 규칙을 문장에 꺼내 놓음. 성격은 문장으로 드러냅니다.
7. **내용 없는 균형 병렬.** 대칭을 맞추느라 내용이 빈 구조. "A도 B도 아닌 C"가 대표적입니다.
8. **들뜬 강조.** 느낌표·이모지로 날의 성격을 강조함(원칙 2).
