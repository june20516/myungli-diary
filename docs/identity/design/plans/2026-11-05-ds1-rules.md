## Global Constraints

* 범위는 **1단계 규칙뿐**입니다. 섹션 제목, 설명 열기, 버튼 조합, 시트는 컴포넌트·요소 단위 규칙까지만 정하고, 어느 화면에 어떻게 놓을지는 적지 않습니다(지휘 범위 보충). 화면 요소를 더하거나 빼는 안을 만들지 않고, IA를 바꿔야 할 이유가 보이면 #801에 코멘트로 남깁니다.
* 고칠 수 있는 곳: `docs/identity/design/`, `docs/contracts/README.md`의 디자인 토큰·컴포넌트 명세 행, GitHub Issues.
* 토큰은 freeze라 **추가만** 합니다. 기존 토큰 값(`space.20` 포함)을 바꾸지 않습니다. 값을 바꿔야 하면 새 토큰을 더하고 명세가 새 토큰을 가리킵니다.
* 아이콘 팩은 Phosphor 2.1.2뿐입니다. 직접 그린 아이콘을 새로 만들지 않습니다(사용자 원문 #14). 다른 시스템의 자산(TDS Figma, SEED Icons, Material Symbols)을 가져오지 않고 규칙만 참고합니다.
* 사용자에게 보이는 글(견본 페이지 화면 문구 포함)에 U+2014, U+2013, U+00B7을 쓰지 않습니다(D93). spec, plan, commit은 괜찮습니다.
* 공개 저장소(D74): 비공개 기록은 경로를 글로만 적고 링크하지 않습니다. 스크린샷을 저장소에 넣지 않습니다.
* 원고를 쓰지 않습니다. 문구는 슬롯·키 이름으로만 가리킵니다.
* IA에 없는 새 단위(섹션 제목, 설명 열기, 버튼 쌍, 구분선)는 컴포넌트가 아니라 **요소**(`elements.json`)로 둡니다. `components.py`가 IA에 없는 컴포넌트를 실패로 보기 때문이고, 2단계에서 IA가 화면에 놓을 때 컴포넌트로 올릴지 정합니다.

## Review Focus

* 기기 글자 크기 1.3배 이상에서 아이콘 크기 규칙(글자 높이 기준)이 아이콘을 키우는지, 고정 px로 남는지. 기대: 글자와 함께 커짐(V30 최소 높이 규칙과 같은 원리).
* en·ja에서 두 버튼 가로 배치가 넘칠 때. 기대: 자동으로 세로로 쌓이고 주 버튼이 위, 두 버튼 높이 같음.
* 설명 열기가 화면 아래 끝 칩이나 양 끝 칩에서 열릴 때. 기대: 화면 밖으로 잘리지 않고 아래 내용을 밀지 않음.
* 동작 줄이기 설정에서 눌림, 화면 전환, 시트. 기대: 이동과 크기 변화는 끄고 색과 투명도만 남김.
* "근거 보기" 글자를 아이콘으로 바꾼 뒤 스크린리더. 기대: 아이콘 버튼이 무엇의 근거인지 읽고(a11y 라벨 슬롯), 터치 영역 48 이상.
