# 계약 1.1.0 (drift #550, D95, #552, #530) Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** REST v1을 `1.1.0`(하위 호환 추가)으로 올리며 drift #550을 따라잡고, D95 설명을 고치고, 합치기 재전송 판정(#552)과 일기의 그날 성격 기록(#530)을 구현합니다.

**Architecture:** 날짜 기록 `diary_days`에 `day_kind` 열을 더해 그날 첫 편을 쓸 때 엔진 결과의 날의 성격을 함께 적고, `Diary.dayKind`(선택)로 돌려줍니다. 합치기는 같은 트랜잭션에 영수증 `account_merge_receipts`(토큰 해시, A, 시각)를 남기고, 토큰이 이미 쓰였어도 같은 A의 영수증이 24시간 안이면 다시 합치지 않고 성공으로 끝내 200 `Me`를 돌려줍니다.

**Tech Stack:** Go, PostgreSQL(goose·sqlc), oapi-codegen, testcontainers

**Spec:** Issue #530, #552, #550, 루트 결정 D90 ①·D95, 서버 spec `docs/specs/2026-10-23-account-delete-merge-purchases.md`(합치기), `docs/specs/2026-10-11-server-mvp-design.md`

## Global Constraints

* 계약은 하위 호환 추가(minor)와 설명(patch)만 합니다(S93). `info.version`은 `1.1.0`.
* `DayKind` 값은 계약 enum `gwiin_day`·`yongsin_day`·`gisin_day`·`ordinary_day` 그대로입니다(`fortune.dayKindValue`).
* 운영 데이터가 없으므로 기존 날짜 기록의 `day_kind`는 채우지 않고 NULL로 둡니다. NULL이면 `Diary.dayKind`를 생략합니다.
* 합치기 영수증 유효 시간은 멱등 기록과 같은 24시간입니다. 지나면 `job retention`이 지웁니다.
* D95: LINE·Google 허가는 떼기·계정 삭제·합치기 어디서도 취소하지 않습니다(server도 app도). 계약 설명에서 "app이 SDK로 취소" 문장을 없앱니다.
* 사용자에게 보이는 글(원고, 페이지)에는 긴 대시·범위 대시·가운뎃점을 쓰지 않습니다(D93). 계약 설명과 결정 로그는 작업 문서라 괜찮습니다.

## Review Focus

1. 같은 토큰으로 동시에 두 요청이 오면 하나는 합치고 다른 하나는 영수증을 보고 200이어야 합니다(422가 아님).
2. 다른 계정(C)이 A의 영수증 토큰 원문을 보내면 422 `merge.token_invalid`이어야 합니다(영수증은 A에게만).
3. 영수증이 24시간을 넘겼으면 같은 A라도 422입니다.
4. A를 삭제하거나 A가 다른 계정에 합쳐질 때 A의 영수증도 지워져야 합니다(삭제 단계 목록).
5. 합치기에서 `profile = other`로 B의 날짜 기록을 고르면 B의 `day_kind`가 A 행에 들어가야 하고, B에만 있는 날짜도 `day_kind`가 옮겨져야 합니다.
