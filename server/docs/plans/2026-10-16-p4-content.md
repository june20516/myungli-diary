# P4 콘텐츠 모듈 Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** writing 원고를 시드로 넣고, 엔진 결과를 언어별 문장으로 렌더해 `getDaily`·`getCalendar`·`getChart`·`getGlossary`와 반응(`putReaction`·`deleteReaction`)이 실제로 응답하게 합니다.

**Architecture:** 변환 도구(`server/seed`)가 writing YAML을 시드 파일 `seed/data/content.json`으로 바꿔 commit하고, `seed` 명령이 그 파일을 `content_templates`에 넣습니다. `internal/content`는 렌더러(NFC → 토큰 → 값 치환 → 조사 → 조각), 템플릿 저장소, 선택 기록(순환·돌봄 상한)을 맡고 다른 도메인을 모릅니다. `fortune`이 엔진 응답과 content를 묶어 화면별 묶음(proto 응답 + 렌더된 슬롯 문장)을 만들고, `httpapi`가 이를 계약 타입으로 옮깁니다.

**Tech Stack:** Go 1.27, `gopkg.in/yaml.v3`, `golang.org/x/text/unicode/norm`, sqlc/pgx/goose, oapi-codegen strict server, testcontainers(`dbtest`), uv + `mlw`(시드 CI)

**Spec:** `server/docs/specs/2026-10-11-server-mvp-design.md` §6(콘텐츠 모듈), §2.2(의존 규칙), §3.3 콘텐츠 표, §5.2·§5.3. 렌더 기준은 계약 "호칭·조사 처리 규칙" v1.1(`docs/identity/writing/guide/honorific-josa.md`, `rules/josa.yaml`, 기준 구현 `docs/identity/writing/tools/src/mlw/{josa,placeholders,terms,markup}.py`). REST 계약 `server/api/openapi.yaml` 1.0.0-draft.4(PR #225).

## Global Constraints

* 처리할 Issue: #55(호칭·조사 규칙과 시드 변환), #129(규칙 v1.1, 용어 id, 값 종류 `text`). 근거 문장 필드는 #167(계약 draft.4)입니다.
* 렌더 순서(guide v1.1): ⓪ 호칭이 없으면 맨 앞 호칭 덩어리 삭제(ko `{name}님, `, ja `{name}さん、`, en `{name}, `) ① NFC(원고와 호칭) ② 토큰 구간·용어 id 기억, `[[`·`]]`·`|id` 제거 ③ 값 치환(`{name}`은 저장된 호칭, 접미사는 원고에 있음) ④ 조사 6쌍 렌더 ⑤ 토큰 구간을 최종 문장 기준으로 다시 계산해 조각 배열 ⑥ ⓪에서 덩어리를 지운 en 문장만 첫 조각 첫 글자 대문자.
* 조사 6쌍과 판정은 `rules/josa.yaml`(`pairs`, `readings`)이 원본입니다. Go 테스트는 `josa.yaml`의 `examples`를 그대로 읽습니다. 판정이 다르면 기준 구현과 `examples`를 따릅니다.
* 호칭은 `vocative: true` 슬롯(`daily.fortune.head`, `chart.ilgan_head`)에서만 씁니다.
* `Segment.term`은 용어 id(`<범주>.<값>` 또는 `tag.<키>`)입니다. 응답에 `[[`, `]]`, `|용어 id`가 남지 않습니다.
* 값 종류: 범주 목록(첫째가 기본 범주, `color`는 element 값), `list:<cat>`(이름을 `", "`로 이음), `number`, `text`(그대로), `none`(원고에 쓰지 않음). 이름이 없는 enum 값은 오류입니다.
* 문장 틀 id = (slot, key, variant). `variant` 값: 유형 슬롯(`daily.fortune.head`·`daily.fortune.tag`)은 `advice`·`state`·`care`, 변주 2개 슬롯(`daily.guide`)은 `1`·`2`, 나머지는 `single`.
* 순환(D57·D59②, spec §6.2): 총운 슬롯만 `advice → state → care`, 새 사용자는 `advice`부터. 가이드 변주 `1 → 2`. 돌봄 상한(W14): 같은 사용자에게 `care`가 하루 2개, 최근 7일 7개를 넘지 않음. 상한은 (날짜, 슬롯)마다 한 번만 셈. 차례가 `care`인데 상한이면 건너뛰고 다음 차례.
* 선택 기록은 (계정, 날짜, 슬롯, 사주 지문 = `profile.BirthHash`)마다 하나입니다. 메시지 키가 같으면 기록을 그대로 쓰고, 다르면 새로 고릅니다. 옛 지문의 기록은 지우지 않습니다. 언어를 바꾸면 같은 (키, 변주, 시드 버전)을 새 언어로 렌더합니다.
* 잠금(D60): 근거 열람 권한이 없으면 모든 `SlotText.evidence`(그 안의 `basis`·`source`)와 `Yongsin.basis`를 뺍니다. `todayReason`, `Glossary.meanings`·`hanja`는 잠그지 않습니다. 권한 판정은 P7입니다. P4는 늘 `locked`인 판정기를 조립합니다.
* 실행 중에 템플릿이 없으면 그 슬롯(선택 필드)을 빼고 Error 로그를 남깁니다(spec §6.4). 필수 문장 필드의 템플릿이 없으면 빈 `segments`로 채우고 같은 로그를 남깁니다(계약 Task 1).
* 이미지는 `server/`만으로 빌드합니다. 실행 바이너리는 writing YAML을 읽지 않고, 시드 파일만 `go:embed`합니다.
* 로그에 호칭·출생 정보·문장 본문을 남기지 않습니다. 제품 코드는 `time.Now()` 대신 `clock.Clock`을 씁니다.
* 공개 저장소(D74): 커밋·PR·fixture에 가격·수익 수치와 비공개 경로 링크를 넣지 않습니다.

## Review Focus

1. 같은 사용자가 두 기기에서 동시에 처음 연 날: 문장이 하나로 정해지고 `rotation_state`가 한 번만 넘어가야 합니다(진 쪽은 다시 읽음).
2. 하루 안에 사주를 바꾼 사용자: 새 지문으로 다시 고르고, 같은 날 같은 슬롯의 `care`는 상한에서 한 번만 세며, 새로 고른 유형이 앞 문장과 같지 않아야 합니다.
3. 판정할 수 없는 글자(가나, 판정표 밖 한자, 기호) 뒤의 조사: 병기형(`이(가)`)으로 나와야 합니다. 토큰 뒤 조사는 토큰 안 마지막 글자 기준입니다.
4. 원고가 아직 없는 슬롯(W1 전, 지금 대부분): 응답이 500이 아니라 그 필드만 비고 Error 로그 하나가 남아야 합니다.
5. 언어 변경 직후 같은 날 다시 연 사용자: 문장 틀은 그대로이고 언어만 바뀌어야 합니다. 그 언어에 원고가 없으면 4번과 같습니다.
