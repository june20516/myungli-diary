# P8-1 알림 기기 API Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** 계약 `registerDevice`·`deleteDevice`(S92)를 `devices` 표와 함께 구현하고, 계정 삭제·합치기에서 기기를 지웁니다.

**Architecture:** 새 도메인 패키지 `internal/device`(저장소 + sqlc `devicedb`)가 등록·해제를 맡고, `httpapi`가 계약으로 옮깁니다. 등록은 한 트랜잭션에서 계정별 advisory lock → 토큰 upsert → 활성 10대 초과분 비활성 순서입니다. 계정 삭제 단계(`account.DeleteAccountTx`)에 기기를 더하면 합치기의 B 삭제도 같은 경로를 탑니다.

**Tech Stack:** Go, pgx v5, sqlc, goose, oapi-codegen strict server, testcontainers

**Spec:** `docs/specs/2026-10-11-server-mvp-design.md` §3(devices 행)·§5.2·§8.2, 결정 S92·S60·S105, 계약 `api/openapi.yaml` `registerDevice`·`deleteDevice`

## Global Constraints

* 계약은 바꾸지 않습니다(REST v1 1.2.0 그대로). 응답 코드: 새 토큰 201, 이미 등록된 토큰 200(같은 `id`), 해제 204, 없는·남의 기기 404 `device.not_found`.
* 계정당 활성 기기 상한 10(S92). 넘으면 `last_seen_at`이 가장 오래된 활성 기기부터 비활성.
* `registerDevice`는 `Idempotency-Key`를 받습니다(멱등 미들웨어 operation 목록에 더함, S60).
* 프로필은 요구하지 않습니다(일정과 같음).
* id는 `uuid.NewV7()`, 업무 시각은 `Clock`에서 받습니다(DB 기본값은 `created_at`만).
* 모든 FK는 `ON DELETE RESTRICT`이고 계정 삭제가 자식부터 지웁니다(S105).
* 주석·로그·오류 문구는 한국어, 기존 파일의 주석 밀도를 따릅니다.

## Review Focus

1. 같은 계정이 동시에 기기 11대를 등록 → 활성은 정확히 10대(lock 없이 각자 10대로 세면 11대가 남음).
2. A 계정의 토큰을 B 계정이 등록 → 200, 기기 `id` 그대로, 주인이 B, A의 활성 수에서 빠짐. A가 그 `id`로 `deleteDevice`하면 404.
3. 비활성인 자기 기기를 다시 등록 → 200, 다시 활성, `last_seen_at` 갱신, 상한 계산에 포함.
4. 같은 토큰을 platform만 바꿔 등록 → 200, platform이 새 값.
5. 계정 삭제·합치기 뒤 그 계정의 `devices` 행이 남지 않음(FK RESTRICT라 남으면 삭제 자체가 실패).

migration:

```sql
CREATE TABLE devices (
    id           uuid        PRIMARY KEY,
    account_id   uuid        NOT NULL REFERENCES accounts (id) ON DELETE RESTRICT,
    fcm_token    text        NOT NULL UNIQUE,
    platform     text        NOT NULL CHECK (platform IN ('ios', 'android')),
    active       boolean     NOT NULL,
    last_seen_at timestamptz NOT NULL,
    created_at   timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX devices_account_active ON devices (account_id, last_seen_at) WHERE active;
```

`UpsertDevice`는 `INSERT … ON CONFLICT (fcm_token) DO UPDATE SET account_id, platform, active = true, last_seen_at`이고 `RETURNING id, platform, (xmax = 0) AS inserted`입니다. `DeactivateOverflowDevices`는 그 계정의 활성 기기를 `last_seen_at DESC, id DESC`로 세워 `MaxActivePerAccount`번째 뒤를 비활성으로 바꿉니다. `Register`는 트랜잭션 안에서 `pg_advisory_xact_lock('dev'를 int4로 한 구분 값, hashtext(account))`(S82 관례, 다른 lock과 구분 값이 겹치지 않게) → upsert → overflow 순서입니다. `Deactivate`는 `UPDATE … SET active = false WHERE id = @id AND account_id = @account_id`가 0행이면 `ErrNotFound`입니다.
