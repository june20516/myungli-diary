# P8-2 job retention 확장 Implementation Plan

> **agentic worker에게:** REQUIRED SUB-SKILL: 이 plan을 task 단위로 구현하려면 suberpower:subagent-driven-development(권장) 또는 suberpower:executing-plans를 사용하세요. Step은 추적을 위해 checkbox(`- [ ]`) 문법을 사용합니다.

**Goal:** `server job retention`이 spec §8.3의 정리, S6의 soft delete 내용 비우기, S113 보관 기간, S119 비활성 기기, Apple 웹 로그인·합치기 토큰의 지난 행 정리를 하루 1번 수행합니다.

**Architecture:** 새 패키지 `internal/retention`(sqlc `retentiondb`, 쿼리 `db/queries/retention.sql`)이 보관 기간 상수와 정리 단계를 한곳에 둡니다. 각 단계는 `Step{Name, Run}`이고, `cli.retention`이 단계를 모두 돌리며 한 단계가 실패해도 나머지를 계속하고 마지막에 `errors.Join`으로 실패를 돌려줍니다. 이전 `ruleset_version` 캐시 정리만 엔진 `GetInfo`가 필요하므로 cli에서 엔진 client를 만들어 넘깁니다.

**Tech Stack:** Go, sqlc(pgx/v5), goose, testcontainers(`dbtest.New`), `clocktest`.

**Spec:** `docs/specs/2026-10-11-server-mvp-design.md` §8.3·§9(캐시 보존), `docs/specs/2026-10-23-account-delete-merge-purchases-design.md` §7(S113), `docs/specs/2026-10-13-apple-web-callback-design.md` §2.5, `docs/specs/2026-10-22-login-providers-merge-design.md` §4.1, 결정 S6·S19·S68·S113·S119.

## Global Constraints

* 모든 기준 시각은 `clock.Clock`의 `Now()`이고, 연 단위 기간은 `now.AddDate(-n, 0, 0)`입니다.
* 정리 단계는 행을 물리적으로 지웁니다. 예외는 S6(일기·일정 행은 남기고 내용만 비움)입니다.
* 보관 기간: 캐시 30일(`created_at`), `idempotency_keys` 24시간(`created_at`), `rate_limits` 1분 창이 끝난 행(`window_start < now − 1분`), 만료된 refresh token(`expires_at < now`), 합치기 토큰·Apple 웹 로그인 만료 + 1일, 비활성 기기 `last_seen_at` + 30일, 미리보기 설치 해시 `used_at` + 1년, 보상 기록 `received_at` + 1년, 결제 기록 5년, soft delete 일기·일정 `deleted_at` + 30일.
* 개인 데이터 표의 deleted 계정 trigger는 INSERT·UPDATE OF account_id만 막으므로 정리 UPDATE·DELETE와 부딪히지 않습니다.
* 단위 `CLAUDE.md`에는 버전을 적지 않습니다.

## Review Focus

1. 회전된 refresh token 사슬(`replaced_by_id`, ON DELETE RESTRICT): 만료 시각이 뒤집힌 사슬(TTL을 줄인 배포)에서도 job이 FK 오류로 멈추지 않고, 아직 살아 있는 토큰이 가리키는 행은 남겨야 합니다.
2. 아직 유효한 결제 구간: 5년 전에 산 구매라도 구간(`entitlement_grants.expires_at`)이 5년 안에 끝났거나 아직 남았으면 구매 행과 구간을 지우지 않아야 합니다.
3. Apple 웹 로그인 만료 행: 같은 subject의 연결 행이 있으면 revoke 대기 행을 만들지 않고(S19), 이미 쓴 행(`consumed_at`)도 만들지 않아야 합니다.
4. 엔진이 내려가 있을 때: 이전 버전 캐시 정리만 실패하고 법정 기간 정리(결제·보상·IP 해시)는 끝나야 하며, job은 실패로 끝나 경보가 와야 합니다.
5. 복구 기간 안의 soft delete 일기와 이미 비운 행: 30일이 안 된 행은 그대로, 이미 비운 행은 `content_purged_at`을 다시 찍지 않아야 합니다.
