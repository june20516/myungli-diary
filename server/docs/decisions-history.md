| S170 (처음 안) | 2026-11-26 | 운영, 개인 정보 | (→ 2026-11-26 같은 번호 S170 개정으로 대체: IAP 뒤 운영 API, 사람 DB 계정 없음) **운영 명령 `server ops`(계정 조회, 권한 부여와 회수, 콘텐츠 열람, 감사 기록 보기, D145 ①, #1321 운영 명령).** ① **로컬 실행:** Cloud Run Job이 아니라 운영자 컴퓨터에서 같은 바이너리로 실행합니다. Job의 stdout은 Cloud Logging(90일, S164)으로 가서 열람 본문이 로그에 남고 터미널로 돌아오지 않기 때문입니다. 연결은 운영자 본인의 Cloud SQL IAM 사용자(S121)이고 연결 값은 `ops.env`(로컬 값 대장 K20) ② **실행자와 시각은 DB가 정함:** `ops_audit`의 `BEFORE INSERT` trigger(`ops_audit_stamp`)가 `at`을 언제나 `now()`로, `actor`를 DB가 인증한 `session_user`로 덮습니다. 어드민 API 전까지 `channel`은 `cli`만 허용하고 `admin_api`는 trigger가 거절하며(psql로 `admin_api`를 넣어 실행자를 임의로 남기는 경로를 막음), 어드민 API를 만들 때 그 경로의 실행자 결정 방식을 다시 정합니다. 명령 인자나 운영자 컴퓨터 시계로 실행자와 시각을 바꿀 수 없고, `SET ROLE`은 `current_user`만 바꾸므로 로그인한 사람이 남습니다. 부여 시작, 회수 시각, 기간 검사도 트랜잭션 안의 DB `now()` 기준입니다. 앱 런타임 `myungli_app`의 `ops_audit` INSERT는 거두었고(retention용 DELETE는 남김), 어드민 API가 생길 때 그 경로의 권한과 실행자 출처를 다시 정합니다 ③ **운영자 등록과 판별:** 운영자 메일은 개인정보라 tfvars에 두지 않고 `gcloud sql users create ... --type=cloud_iam_user`로 추가합니다. `migrate up`이 로그인 가능하고 이름에 `@`가 있고 `.iam`으로 끝나지 않는 역할(사람 IAM 사용자)을 `myungli_ops` 구성원으로 넣습니다. 빼기는 DB 사용자 삭제 ④ **`myungli_ops` 권한(S137의 `myungli_app`과 같은 묶음 방식):** `accounts`, `entitlement_grants`, `purchases`, `diaries`, `diary_days`, `schedules` SELECT, `auth_identities`, `devices`, `profiles`는 운영 쿼리가 쓰는 칸만 칼럼 단위 SELECT(제공자 subject, Apple 토큰, 알림 token, 출생 정보 해시, 알림 설정은 못 읽음), `entitlement_grants` INSERT와 `revoked_at` UPDATE와 id sequence USAGE, `accounts`의 `updated_at` UPDATE(운영자 부여의 계정 행 `FOR SHARE` 잠금에 필요, 값은 바꾸지 않음), `ops_audit` INSERT와 SELECT뿐 ⑤ **출처 `operator`와 계약 변환:** 운영자 부여의 DB 출처는 새 값 `operator`이고, 앱 계약 `Insight.source`에는 새 값을 더하지 않고 S125처럼 `ad_free` 묶음은 `ad_free_pass`, `insight` 단독은 `rewarded_ad`로 보냅니다(D138). 계약 변경 없음 ⑥ **회수 범위:** `operator`, `rewarded_ad` 행만 거둡니다. 구매에서 생긴 `ad_free_pass`는 장부 다시 잇기와 어긋나므로 거절하고 스토어 환불로 처리합니다. 부여 기간은 지금부터 366일 이내 ⑦ **감사 표 `ops_audit`:** 조회와 열람도 기록합니다. 기록에 실패하면 결과를 출력하지 않고, 거절된 부여와 회수는 감사 행을 남기지 않습니다. trigger가 UPDATE와 TRUNCATE를 언제나, DELETE는 2년 지난 행만 허용합니다. 열람 기록의 `target`에는 계정 id와 항목 id, 개수만 남기고 본문, 호칭, 출생 정보는 넣지 않습니다 ⑧ **2년 보관:** `job retention`이 2년 지난 감사 행과 끝난 지 2년 지난 `operator` 부여 행을 지웁니다(접속 기록 보관 기준, 수집과 보관 대장과 처리방침 반영은 #1376으로 지휘에 보고) ⑨ **합치기에서 옮기지 않음:** 계정 합치기는 구매 구간만 옮기고 운영자 부여 행은 옮기지 않습니다(보상 구간과 같음) ⑩ **보이지 않는 것:** 요청 로그에 계정 id가 없고 앱 버전은 저장하지 않으므로 계정별 접속 기록은 `last_active_at`과 기기 `last_seen_at`까지입니다. 목적별 운영 기준은 문서에 적지 않습니다(D145 ⑤⑥) ⑪ **남는 위험과 다음 조건:** `myungli_ops` 구성원은 `diaries`, `schedules`, `profiles`를 직접 SQL로 읽을 수 있고 이 열람은 감사 행을 남기지 않습니다. 지금 운영자는 프로젝트 소유자 한 명이라 받아들입니다. 프로젝트 소유자가 아닌 운영자를 등록하기 전에 콘텐츠 열람을 `SECURITY DEFINER` 함수로 옮기고 `myungli_ops`에는 그 함수의 EXECUTE만 줍니다(함수 안에서 감사 행을 함께 씀) | spec 2026-11-26-ops-commands-design, `docs/runbook/ops.md`, D145, D138, S105, S121, S125, S137, S164, #1321. 사용자 영향: #1376(감사 기록 2년 보관, 운영자 열람의 수집, 보관 대장과 처리방침 반영) |
